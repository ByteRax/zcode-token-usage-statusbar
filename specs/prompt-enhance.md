# 增强提示词按钮（模型 chip 左侧）

## 产品规则

- 会话输入框底部工具条、模型 chip（宿主 `[data-testid="chat-model-select-trigger"]`）左侧渲染一颗星芒按钮（`.zu-enhance`）；模型 chip 缺位时回退挂用量圆环（`chat-context-usage-trigger`）左侧，两者都缺不挂。Highspeed 锁定模型等宿主特殊分支下跟随锚点自然隐藏，不做额外猜测。
- 点击相位状态机：`idle` 点击发起增强；`enhancing`（loader-circle 旋转 + `aria-busy`）期间**再点 = 取消**（v344.1）：渲染端立即置 settled 丢弃迟到回包（不再应用结果）并恢复初始可点击态，同时经 `prompt-enhance-cancel`（载荷带在途 requestId，fire-and-forget）让主进程 abort 在途请求——`inject-main` 持有 requestId 到 AbortController 的在途表，`enhanceText` 接收外部 signal，取消返回 kind:"cancelled" 且不再重试，重试退避等待同样可被打断；该动作属主进程白名单，旧主进程吃 unknown 兜底回执，取消的「立即恢复+不应用结果」仍成立，仅「真中断网络请求」需重启加载新分支。- **会话切换（v344.3）**：发起时锚定会话身份（`enhanceSid = instSid || pickedSid`）。回填前先校验会话未变，变了则以「会话已切换，本次结果未应用」丢弃（区分于同会话内编辑导致的「草稿已变化」），**绝不把结果写进切换后的新会话草稿**——内容比对在两会话草稿恰好相同时会漏判，会话身份是权威闸。dispose/热更路径（`restoreEnhanceBtn(true)`）补发 `prompt-enhance-cancel` 中断在途请求止损额度；临时无锚只摘除 DOM、保持任务及超时；开关关闭则取消在途任务。

**撤销相位已删除（v350.1，用户拍板 2026-11-15：去掉「撤销增强，恢复原文」状态展示）**：应用成功（写入确认）后按钮直接回 `idle`，不再展示 20 秒撤销窗、不再有撤销点击路径；聊天历史采集时机不变（应用成功即记录）。原撤销窗守卫（草稿基准/会话校验/自动收窗）随相位一并移除，回填前的会话与草稿比对守卫（防覆盖用户编辑、防跨会话写入）不受影响。
- 增强 = 读取当前 composer 草稿全文（`__zcodeLexicalInputE2E.getText()`，`data-e2e-lexical-bridge === "ready"` 才可用）→ 主进程用当前会话模型对应凭据发起补全改写（Anthropic 流式聚合，其余非流式）→ 回填前核验会话身份和草稿全文，一致才 `setText()` 整体替换并重读确认（重读比对按 CRLF→LF 归一，v357：宿主桥读回可能规范化换行，逐字比对会把已成功写回误报成「写回失败或草稿已变化」）。会话身份未知、输入桥不可用或草稿变化时不应用结果。空草稿不发请求。
- **draft 会话放行（v354）**：新会话在发出首条消息前宿主不分配会话 ID（`data-session-id="draft"`，`SessionPane.tsx` 的 `sessionId ?? "draft"`），此类 pane 同样可增强——仅增强链经 `readPaneScope(..., allowDraft=true)` 显式放行 draft，发起身份键 = `"draft"` + workspace scope（scope 属性与 sessionId 无关，draft pane 照常携带）；scope 仅作渲染端回填闸，主进程 prompt-enhance 链不消费任何 sid/scope。在途时用户发出首条消息（draft→真实 sid 晋升）按既有「会话已切换」丢弃，绝不回填。共用归属链的其余消费面（quota 上报、状态条、远端路由、`getScope`）不传该参数，draft 一律维持拒绝——draft scope 绝不进上报链。非 custom 模式下模型闸先于会话闸，draft 且 chip 无模型时提示「未识别当前模型」。
- 模型归属：优先渲染端实时选择（`v4-model-config` 的 `data-provider`/`data-model`，与额度 chip 同链），缺省回退快照 `last.provider_id`/`model`。主进程只接受 `{providerId, modelId, text}` 三元组；凭据解析失败、无 key、协议不支持一律 fail-closed 回错误，绝不显示假成功。
- 增强 prompt 只改写不回答：语言跟随草稿（混合保持混合），~800 字符是软目标，长草稿以保真为先；保留代码/路径/命令/报错/数字/URL 及已有结构，不发明事实、技术栈或无关要求。用户草稿按 JSON 字符串序列化作素材，不能把此包装当成绝对的提示词注入防护；不新增无用标题或围栏，但保留原有代码围栏。仅正式答案字段可回填，只有思考内容、流错误、未完整结束的响应及清理后空文本均失败。仅发送当前草稿，不附会话历史、仓库文件或个人记忆。
- 开关 `enhance_enabled`（config.json 顶层扁平键）：缺省开，显式 `false` 关（与 `quota_enabled` 同语义）；主进程在动作入口 fail-closed 校验，渲染端按钮显隐与 ⚙ 面板开关真值跟随推送面 `enhanceEnabled`。

## 增强专用供应商配置

- 状态条设置新增「提示词增强」独立分区；右键增强按钮打开对应分区，设置已打开时切页，不触发增强、取消或撤销；齿轮导航和键盘同样可进入。
- 用户级配置全窗口共享：设置页以单一「配置来源」选择承载三态——跟随当前会话（内部默认模式）、ZCode 已有供应商（自定义+host）、手动配置／厂商预设（自定义+manual）；隐藏模式位由来源联动，持久化格式不变。自定义配置缺失、损坏、来源失效或请求失败均明确报错，不静默回退。
- 自定义来源支持「从 ZCode 选择已有供应商」实时引用（含凭据可用的套餐源：BigModel/Start Plan 等，凭据由主进程 planKeyOf 解析，协议恒 anthropic）、「厂商预设」和手动填写；预设仅填经核实的地址与协议，不提供 Key。导入仅按显式选择的供应商 ID 解析，界面不回传保存过的 Key；宿主删除、禁用或目标身份（协议、地址）变化时停止使用并要求重新确认。自定义模式下选择 ZCode 来源或打开已保存的 ZCode 来源时自动拉取兼容供应商列表，恢复已保存 provider ID；明确区分加载中、空列表与读取失败，允许手动刷新。默认模式不展示自定义来源与字段，但保留已保存值，切回自定义不丢失。
- 表单支持 Base URL、协议（OpenAI Chat Completions、OpenAI Responses、Anthropic Messages）、API Key、模型；Key 的保留、替换、移除是不同操作。Key 字段留空表示保留；移除已保存 Key 通过显式低视觉权重操作及二次确认完成，不用常驻复选框。改变目标不携带旧 Key；改变来源或协议后须重新选择/确认模型。切语言或并发保存不应丢失未提交输入。
- 「拉取模型」仅请求当前表单快照对应的供应商、展示有界模型列表并选择一个增强模型，也可手动输入；旧请求回包不得覆盖用户后续编辑。不调用会修改宿主配置的模型应用或修复接口，不访问额外公共目录。拉取成功不等于增强模型可用，任何操作均不修改宿主聊天供应商与模型配置。保存为主按钮，拉取模型为次按钮，样式遵循 ZCode 设置中的语义色与尺寸层级。供应商列表（5 分钟）与模型列表（按目标 10 分钟）在实例内存中缓存：打开设置、切换来源/供应商时优先用缓存渲染，不发请求；「刷新」按钮与「拉取模型」始终强制走网络并更新缓存，缓存过期后重新拉取。供应商列表另有运行目录硬盘缓存 `enhance-providers-cache.json`（0600，仅 id/名称/地址/协议，无凭据）：每次拉取自动回写，打开设置先以硬盘缓存秒出列表，随后自动拉取新鲜数据覆盖。切换供应商时先清空旧模型列表、命中模型缓存则先显示缓存，并自动以该供应商草稿拉取最新模型列表（等价「拉取模型」，凭据由主进程解析）；仅对显式选中的供应商发起。
- HTTP 或可识别的本机/内网地址不显示常驻确认复选框；目标旁显示风险警告，发送 Key 或草稿前针对具体目标作明确确认，目标变化后重新评估。用户可选择继续；URL 校验不代替 DNS 或代理层验证，禁止跟随重定向。手动来源拉取模型时，只有地址和协议均与已保存的手动目标一致才可复用已存 Key，否则必须提供新 Key。
- 独立配置 `enhance-provider.json` 存放于运行目录，手工 Key 是本地明文，不写普通配置/日志/诊断/命令行或状态推送；用户输入和一次性提交期间仍短暂经过渲染端。POSIX 限属主访问；Windows 无等价属主安全语义，配置写入/拉模型/历史落盘按平台 **fail-closed 恒拒**（`runtime_lock.update_enhance_provider` 平台门 raise + 主进程 models/save 早退门），快照带 `enhanceProvider.platformLimited` 供渲染端按平台区分提示文案（不误导「检查权限或重启」，v357）；开发目录忽略秘密文件。配置及 Key 一体事务、锁内重读与版本冲突检测；损坏、权限失败和未知版本不得按空值覆盖。
- 新动作使用能力与协议版本握手，新旧主桥、热模块或 helper 不兼容时自定义模式不可用并提示重启，不能退回旧动作把草稿发到非预期供应商。模型列表与增强绑定配置代际；切配置时尽力中断旧请求并拒绝迟到结果，已发送的数据不能撤回。
- 手动/预设来源仅访问用户选择的 HTTP(S) 目标；拒绝 URL 中的用户名、密码、片段及不支持的查询串。HTTP 或可识别的本机/内网目标按上述规则提示并在敏感请求前确认；请求禁止重定向跟随，不把代理/DNS 层保护扩大为未经实现的保证。
- 增强分区统一宽度 `min(100%, 880px)`，表单铺满分区；局部字段无外边距，以容器 8/12/16/24px 间距分层，控件基准高 36px 并允许宿主大字号增高。模型输入与拉取按钮同一行，极窄时自然换行；供应商名称与域名/协议分层、选中含文字标记，列表有界滚动。Key 未保存时隐藏移除操作，模型请求状态就近展示；保存行使用轻量分隔线与两端对齐。保持原有模式、来源、凭据事务及目标确认语义。
- 宿主卡片必须显式选中，未选中时保存或拉取前给出「请先选择供应商」，不发送请求。刷新列表保留仍有效的选中项及目标元数据，失效项明确要求重选。
- 模式及来源切换只改变编辑草稿，保存成功前不改变请求路由；显示真实生效状态和未保存状态。保存及拉取期间记录表单快照与配置版本，迟到回执不覆盖后续输入；多窗口版本冲突不得静默覆盖。

## 设置页增强测试

- 测试区位于自定义模型区之后、保存区之前；默认模式位于摘要之后。测试草稿和纯文本结果仅属于设置实例，不写聊天编辑器、持久化配置或诊断；显式点击才发送，提示草稿会发送且可能产生费用。空白及超过 20000 字符拒绝，不截断。结果保持原样并可复制，耗时由本地时钟测量。
- 测试仅使用当前正在编辑的配置：自定义模式以表单快照发起，允许未保存修改；主进程按快照解析（宿主来源按 ID 实时解析并核对地址与协议，手动来源仅本次请求使用输入框中的 Key，或目标与已保存手动目标一致时复用已存 Key），凭据只在主进程内存使用、不落盘不回传。默认模式仍要求可验证的当前 pane 实时 provider/model 与 scope；已保存模式为自定义时不按会话模型测试。测试不写入配置，保存状态与测试状态独立；风险目标继续走主进程原生确认。
- 实例持有请求 ID、输入及配置身份快照、启动时间与 UI 计时器；最多一笔，取消、草稿或配置变化、切区、关闭、销毁均发送现有取消动作并遗忘回调，旧响应不得覆盖新状态。语言重建保留测试输入和已完成结果，在途按取消处理。结果仅通过 textContent 展示；剪贴板仅用户点击复制时写入。风险目标继续复用主进程现有确认及禁止重定向策略。
- 测试区域按容器宽度双列或单列；loading、成功、错误、取消及结果过期与保存状态独立；不能把测试成功当作配置保存成功。失败时展示主进程返回的分类错误与有界接口响应摘录（≤500 字符、去除控制字符，仅为用户自己的请求响应），文字用错误语义色；取消与过期保持中性色。关闭设置不再覆盖已结束的测试状态，仅取消在途请求。

## 增强历史记录

- 悬停增强按钮显示「最近增强记录」面板（替代原纯文字提示，600px、上方弹出、内部滚动）：最近 3 条卡片（供应商/模型快照、原始与增强文本两行预览可展开、Token·时间·耗时统计行）、Footer 查看全部与清空（二次确认）。点击按钮仍是增强，悬停移入面板保活，Escape 关闭；历史读取失败可重试，空记录显空状态。**视口钳位（v355）**：每次显示/内容重绘后按面板实测高三档放置——按钮上方够→bottom 锚定（原行为）；上方不够而下方够（≥min(面板高,320px)）→翻到按钮下方（箭头翻转到面板顶部朝上）；两侧都不够→上方贴视口顶并钳 maxHeight，`.zu-eh-scroll` 内滚，任何档位面板顶缘都不得越出视口。
- 采集口径：聊天增强仅在结果**成功应用**后记录（source:"chat"）；设置页测试成功记录 source:"test"；未应用/取消/失败不记。记录含 requestId 去重、供应商与模型快照（不读当前值覆盖旧记录）、createdAt ISO、durationMs（单调时钟）。
- Token 用量来自模型响应：OpenAI Chat `usage.prompt/completion/total_tokens`、Responses `usage.input/output/total_tokens`、Anthropic 流 `message_start`+`message_delta`（delta 为累计输出，不重复相加）；缺失显示「Token 未提供」，不用字符数冒充，不重复计入重试。
- 持久化：运行目录 `enhance-history.json`（0600，仅文本/快照/用量/时间，无任何凭据），上限 100 条、30 天自动清理（写入与读回均裁剪）；受设置分区「在本机保存增强历史」开关控制——默认开启写入磁盘（v363 起：配置缺省视为开启，仅显式关闭后仅内存保留——本会话可用、重启清空；关闭不删除此前已落盘的文件，重新开启后文件保留、记录按上限裁剪加载，可在历史面板清空）；Windows 上落盘链整体关闭（平台门恒拒），历史仅本次运行内存可用、重启清空，勾选说明与 EP 分区状态文案均注明该限制（v357）。开启落盘时删除/清空立即同步 UI 与文件（关闭态仅清内存、文件保持原样）；确认交互统一走 `zuConfirm` 自绘弹框（复用压缩确认弹框外壳样式，不用 window.confirm，规则见 overlay-ui.md §4）。
- 查看全部历史为独立浮层：高密度表格布局，默认一行一条（约 44px），点击行展开三栏详情（供应商·模型 / 原始文本 / 增强文本 ≈22%/39%/39%，增强正文用中性背景而非彩色色块），来源·Token·完整时间·耗时合并为详情底部一行元信息（分隔线下横排，窄窗随容器查询融入流式），仅允许一条同时展开；展开身份按记录 id 保持，排序/筛选/翻页后不错位。支持来源/供应商/模型/时间筛选（供应商与模型下拉从数据动态生成）、关键词搜索（200ms debounce；IME 组合期间挂起重建、compositionend 后再刷新，重建后恢复搜索框焦点与光标——v357：整面板 innerHTML 重建会销毁输入框，强制取消拼音组合并把焦点打回 body）、排序（时间/Token/耗时，点击列标题切换升降序，null 排末尾）、分页（默认 20 条/页，可选 50/100）。行操作列复制（增强结果）与删除（确认）；详情内分别复制原文/增强结果。面板宽度 min(1200px, 100vw-32px)、高度 `auto`、max-height `min(85dvh,760px)`——数据少时内容自然撑开不出现大面积空白，数据多时表区独立滚动；表头/数据行共用一套 `<colgroup>` 列宽（table-layout:fixed）保证严格对齐。供应商列优先显示真实显示名：套餐源按内置 PLAN_SOURCES 同源映射（`account:*` → 「BigModel Start Plan」等），其余原样显示，title 悬浮完整原始 ID。Header 左右分组：左=图标+标题+总数徽标，右=清空记录（图标文字横排、hover 危险色）+关闭（≥32×32 命中区，Escape 同效）；筛选行搜索框弹性填充（最小约 240px）+ 四个统一高度/圆角/边框的筛选器。分页页脚仅在结果超过 1 页时渲染，单页/空态不显示页码与每页选择器。响应式按面板实际宽度（容器查询 + 渲染时列裁剪）：<900px 合并供应商/模型为「供应商 / 模型」列、详情转两栏，<640px 隐藏原文/增强摘要列、详情纵向排列。样式限定 `.zusage-enhance-full` 作用域，图标统一 24 viewBox currentColor SVG（优先复用 EH_ICON 既有图标集）。性能边界：仅面板打开/搜索/筛选/排序/分页变化时构建 DOM，禁止热路径调用；对 1/20/100 条数据均不整表渲染全文滚动。

## 生命周期与失败契约

- 在途状态归实例，不归按钮 DOM：锚点临时消失只摘按钮，保留等待计时与 busy 相位；重新挂载继续显示同一任务。主动关开关、实例 dispose/热更或渲染端超时则置 settled、取消主进程请求并拒绝迟到回填。
- 主进程以窗口和 requestId 共同标识请求；同窗口重复 ID 静默拒绝（不能以相同 ID 回执消费原请求回调），窗口销毁只取消该窗口任务；结束清理必须校验条目身份，旧请求不能删除新请求。回填使用分栏可信 scope（会话、工作区、远端身份）再次核验；身份不可得时拒绝；draft 会话经增强链显式 `allowDraft` 放行（见产品规则 v354 条），其余消费面维持拒绝。草稿含结构化 mention 节点时拒绝增强（整体文本写入会丢失引用语义），不支持序列化且草稿含可识别引用时亦拒绝。
- 每次尝试的 30 秒覆盖请求及响应体读取，外部取消优先于超时；用户取消不重试，5xx、网络错误及超时最多重试一次并有可取消退避，4xx 和确定性解析错误不重试。失败或取消绝不返回部分结果；清理计时器、监听器及读取器。
- 流式响应须确认正常结束，不接受错误事件、截断或中断后的部分内容；允许尾行无换行和 UTF-8 跨块。Responses 多个最终文本块按顺序拼接；仅思考字段不算最终结果。

## 状态所有者与接口

- 渲染端（`src/overlay/11-instance-toolbar-chips.js` 实例闭包）拥有按钮 DOM、相位、busy/undo 定时器与草稿快照；实例 dispose / 关开关 / 锚点消失一律摘除节点，新代清扫选择器含 `.zu-enhance`。
- 主进程 `model-puller.cjs` 拥有凭据解析与 LLM 调用（`enhanceText`）：套餐源（`PLAN_SOURCES`，issue #336 起覆盖宿主 6 个套餐 id：bigmodel/zai 的 individual/team/start-plan）与 api-key 型自定义供应商（`provider_config.json` 的 `access.apiKey`/`api.baseUrl`/`api.type`）两路；三协议（anthropic-messages / openai-chat-completions / openai-responses）。宿主旧形 `builtin:*` 套餐 id 经 `planAliasId` 在拉模型/写入/探测/增强四入口归一为 `account:*`。套餐源鉴权默认**优先宿主对话同款** `v2/config.json` 的 `builtin:<plan>` provider `options.apiKey`（同目录并置文件，宿主 anthropic 端点 `/api/anthropic` + stream:true 实测正常），缺失/`enc:` 密文时回退 credentials.json OAuth token——**OAuth token 直连 messages 端点被网关以 500「网络错误 code 1234」拒绝**（2026-11-13 实测，stream 真/假、有无 UA 均复现），不得改回；例外与限制（issue #336，2026-11-14 实测定案）：`account:bigmodel-start-plan` 的推理与 coding plan **同走 `open.bigmodel.cn/api/anthropic`**，凭据=宿主在 bigmodel 账号下发放的**项目 API key**（名字 `zcode-api-key`、`usageScene=CODING_PLAN`、`id.secret` 形态，宿主已写入 v2 config 的 `builtin:bigmodel-coding-plan` 条目；本机 x-api-key/raw/Bearer 三头形实测 200）。此前按旧 config 注释打 `zcode.z.ai` + 会话 JWT 是双重错误（网关错+凭据错 → WAF 3012/401）；`zcode.z.ai` 仅承载计费（`billing/balance`，`zcodejwttoken`+`X-Device-Mid`）。`account:zai-start-plan` 走 api.z.ai anthropic + OAuth，端点未实测（无 zai 测试账号）。纯 start-plan（无 coding plan config 条目）账号回落 OAuth 会被 500 拒，需 GLr 项目密钥发放流程（未实现前诚实报 auth）。zai 团队与个人共享宿主同一 builtin 凭据条目，列表按同条目只列首档防重复行（credKey 兜底方向可能列出未开通套餐的假行，属已知取舍）。anthropic 协议走 SSE 流式聚合（`content_block_delta` 累积）；5xx/超时/网络类失败自动重试一次（1.2s 退避、单次 30s、总预算 ≈61s 留渲染端 75s 兜底内），凭据/路径/协议类不重试。凭据只在主进程内存与目标供应商请求中使用，不落盘、不进日志、不回传。
- 通道：渲染端 `pluginRequest("prompt-enhance", {providerId, modelId, text}, done)` / `pluginRequest("enhance", enabled, done)`，沿用 `__zusagePluginRequests` 轮询协议与 `__zusagePluginResult` 回执；主进程 `inject-main.cjs` 白名单分支校验形状（providerId ≤160、model ≤200、text 1..20000 字符）后分派。旧主进程不认识动作时回执 `unknown action`，渲染端按错误相位提示，不挂起。
- 配置开关经 `updateConfig` 原子事务写 `enhance_enabled`，保留未知键与用户显式值；⚙ 面板开关乐观更新，失败回执后回滚勾选态。
- 本功能是用户主动触发的生成式调用，会向当前供应商发送草稿文本并消耗额度；不启动后台周期调用，不影响统计/额度/MCP 查询协议，stdout 契约不变。

## 验收场景

1. 输入草稿点按钮：按钮转旋转态，回包后草稿被增强文本整体替换并立即回到可再次增强的初始态（无撤销窗）。
2. 增强期间继续编辑草稿：回包后不覆盖，按钮短暂警示态提示冲突，原文保留。
3. 空草稿点击：不发起请求，警示态提示「先输入内容」。
4. `enhance_enabled: false`：按钮不渲染；动作仍被主进程拒绝（双保险）。
5. 无凭据供应商（如未配置 key 的 custom）：回执 fail-closed 错误，警示态显示原因，绝不静默成功。
6. draft 会话（新会话未发首条消息）输入草稿点按钮：正常发起增强且回包回填；增强在途时发出首条消息（会话晋升出真实 sid）后回包落「会话已切换」警示，草稿不被改写。
7. draft 会话 pane 缺失 workspace scope（桥属性与 fiber 候选均不可得）：仍提示「未识别当前会话，暂不能增强」，不发起请求。
8. draft scope 不进上报链：`getScope`/quota 上报面对 draft 返回空，归属链其余消费面行为与 v354 之前一致。
