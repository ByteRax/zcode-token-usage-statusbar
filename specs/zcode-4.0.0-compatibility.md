# ZCode 4.0.0 自动压缩引擎兼容

## 范围与规则

- `engine-patch.cjs` 的 `ENGINE_TARGETS` 表首登记 ZCode 4.0.0 样本引擎（Windows 实测登记，macOS 桌面 4.0.0 同字节复核）。由引擎补丁器负责识别、应用和还原；原版 `zcode.cjs` 以 SHA-256 优先识别，`getAutoCompactThreshold` 的判定表达式使用 `$ue(e.bufferTokens)` 和 `fZo`，全文件必须唯一命中。
- 锁表纪律：表首（4.0.0）独占 `ANCHOR`/`REPLACEMENT` 常量引用；旧表首 3.19.1 同步滚动为显式 `anchorFor("Uue","KKo")` / `replacementFor("Uue","KKo")` 字面量，防止旧条目静默继承新版本锚点。3.19.1 指纹与锚点不变。
- 沿用同版本漂移规则：指纹不匹配时，只有桌面 build 匹配登记版本（含 `4.0.0.x` 前缀）且该版本锚点全文件唯一才应用；锚点缺失或重复则拒绝写入。3.19.1 及更早条目保持自身指纹与锚点。配置键、阈值计算、未配置时的宿主默认行为均不变。
- 共享模块同步到插件副本。客户端引擎已有同款补丁时重新识别，不重复写入；补丁写入引擎文件后等宿主引擎子进程下次 spawn（新会话或重启客户端）生效。桌面渲染桥不新增 4.0.0 登记，继续由安装链自动推导，不改变离线 CLI 的版本限制。

## 验收

| 场景 | 预期 | 验证 |
| --- | --- | --- |
| 校验过指纹的 4.0.0 原版引擎 | 在临时副本应用成功；第二次不改字节；产物语法有效；还原后与原版逐字节相同 | `tests/engine-patch.test.cjs` 登记表与隔离行为回归；真实引擎锚点全文件唯一命中（grep 计数 =1，macOS 4.0.0 复核） |
| 4.0.0 已有同款补丁 | 识别为 `applied`，不改写原文件 | 真实的已补丁引擎副本 |
| 同版本漂移、不同版本或锚点不唯一 | 仅匹配 4.0.0 build 且新锚点唯一时允许漂移兜底；未知 build 或旧锚点仍拒绝；旧登记条目不受表首滚动影响 | `tests/engine-patch.test.cjs` 的锁表守护用例（含「旧条目改回常量引用」变异杀灭） |
| 实机部署 | 新引擎上报 `unsupported_build` 的存量装机，部署后随主进程热换转为 `applied`/`4.0.0`，`lastError` 清空 | Windows 实机实证（登记时）；macOS 4.0.0 部署后哨兵与引擎字节复核 |
