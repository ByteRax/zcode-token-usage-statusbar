# 套餐 GLr 凭据换发（model-puller 增强链）

状态：已实现（本规格随实现提交）。逆向依据：宿主 3.19.1 引擎 bundle（`zcode.cjs`）`ProjectAccessTokenClient` 类与 3.19.1 runtime builtin 配置，2026-11-21 本机（Windows，宿主 3.19.1）实机复核。

## 背景

宿主 3.19.x 把内置套餐 provider 的 `access.type` 改为 `zhipu-account` 并**运行时内存换发凭据**：3.18 时代写进 `~/.zcode/v2/config.json` 的 `provider.{builtin:*}.options.apiKey`（GLr 项目 key 明文）不再存在（issue #429 后续实机确认：切换模型选择即可用套餐，全程无 config.json 落盘）。插件增强链 `planKeyOf` 的「v2 条目 key → OAuth 兜底」两条路在 3.19.1 上全部失效（OAuth 直连 messages 被网关 500 code 1234 拒，v344 实测；#430 已把 start-plan 收口为 plan_auth，但 individual/team 仍走必败 OAuth 兜底）。

## 宿主协议（逆向定案）

- **凭据换发**：`POST {origin}/api/biz/v1/organization/{organizationId}/projects/{projectId}/api_keys/{apiKeyId}/access_tokens`，头 `Authorization: Bearer <OAuth access_token>` + `Content-Type: application/json`，体 `{clientType:"zcode", clientVersion:<宿主 appVersion>}`；响应 `{code:200|0|"200"|"0", msg, data:{enabled:boolean, accessToken:string}}`——wire 凭据字段是 **accessToken**（2026-11-21 真实端点实测；#431 曾误按宿主缓存内层的 token 字段名解析，真机恒 parse 失败，#432 修正并兼容 token 别名）。`enabled:false`、code 非 200|0、凭据非非空字符串（trim 后）均按无凭据处理；HTTP 404 = location 失效（宿主会删除 location 重新发现）；429/5xx/网络类宿主带退避重试。
- **定位（location）**：credentials.json 键 `project-key-location:v1:` + `encodeURIComponent(JSON.stringify([origin, family, accountId, team, 1, "non-team"]))`（本机实测：`[ "https://bigmodel.cn", "bigmodel", "<accountId>", null, 1, "non-team" ]`）；值=`{organizationId, projectId, apiKeyId}` 的 JSON 经 credentials.json 同款信封加密（`enc:v1/v2`）。accountId 直接取自键名，**不需要**解析 `oauth:bigmodel:user_info`。
- **发现链**（location 缺失时宿主走 getCustomerInfo → 选 org/project → 列/建 `zcode-api-key`）：**插件不实现**——location 缺失说明宿主从未给该账号发放过 coding key，增强无凭据可用，fail-closed 报 plan_auth 与现状一致。
- **路由**（权威来源=`<v2>/runtime/provider/<platform>/<hostVersion>/endpoint-*/zcode-builtin.json` 的 `account:*` 条目 `api.baseUrl`，3.19.1 实测）：`account:bigmodel-start-plan → https://zcode.z.ai/api/v1/zcode-plan/anthropic`、`account:bigmodel-individual-coding-plan`/`team → https://open.bigmodel.cn/api/anthropic`。start-plan 在 open.bigmodel.cn 用项目 key 虽曾 200（v344，raw key），但换发 token 的权威端点以 runtime 配置为准。
- **zcode.z.ai 会话网关的鉴权分流（2026-11-21 真机实测补篇）**：GLr accessToken 是 bigmodel.cn 项目域凭据，打 zcode.z.ai 恒 401——该路由改用 credentials.json 的 `zcodejwttoken`（会话 JWT）+ `X-Device-Mid` 必带头（同目录 telemetry-state.json/onboarding-record.json 的 deviceMid，缺头实测 400 code 3001；额度链 zcode-start 适配器同款口径，OAuth/access_token 打 zcode.z.ai 实测 401）。bigmodel.cn 路由维持 GLr token。凭据序：可用 v2 条目 key → 路由分流（zcode.z.ai=**仅**会话 JWT——条目 key 属 open.bigmodel.cn 端点，无设备头打 zcode 恒 400 code 3001，不用于该路由，会话不可得即以条目 key/GLr 迁移表值路由；其它=GLr）→ plan_auth。 2026-11-21 真机终验：start-plan 全链（换发省略 → 会话 JWT + X-Device-Mid → zcode.z.ai → 200 增强）与 individual 全链（GLr 换发 → open.bigmodel.cn → 200 增强）均实测通过；#429 报告者当年在 zcode.z.ai 实测的 405/3012 WAF 拦截未复现——X-Device-Mid 设备头即客户端身份关键，插件带齐该头即被放行。 同日补充实测：zcode.z.ai 对话端点的 3012 WAF 为**间歇性**（同形请求 16:38 200、16:40 起 405，billing 同头形正常——网关侧状态非客户端可判定）。**双路由降级**（本条为权威行为）：start-plan 主路由（zcode.z.ai + 会话 JWT）遇 HTTP 404/405（kind path）或 401 时自动改走 open.bigmodel.cn + GLr token（该端点接受项目域凭据，individual 全链实测 200；403 与 server 类不降级——server 就地重试与降级语义打架）；**降级腿限单次尝试**（双腿满配最坏墙钟可越过渲染端 75s 兜底）；**错误摘录脱敏按本腿实际发送的凭据**（runAttempts per-leg legKey，后置 review R3-A/D：降级腿复用主腿 secret 会把 GLr token 原样带进 balance detail 回渲染端）；会话凭据缺失时直接以表值路由为主路由；降级成功或给出更可行动的 1113 balance 结果时采信降级结果，双败保留主路由诊断。
- **团队套餐是独立计费池（issue #442，2026-11-22）**：GLr location 只承载个人项目三元组（键名 `team===null`，本机实测样本），对团队 providerId 照旧取个人凭据会把团队会话的增强请求打到个人池——个人池无资源包即恒 429 1113（「套餐额度或资源包不足」），团队池再有额度也用不上；v2 条目 key 同理（宿主对 individual/team 共用同一 `builtin:bigmodel-coding-plan` 条目，key 属个人项目）。**团队凭据不取 location，改走额度链同款三步换发**（src/quota/03-adapters-plan.cjs `ensureTeamPat`，宿主 ProjectAccessTokenClient 只读子集）：setting.json（恒在 HOME/.zcode/v2）`providerFamilyConnectionSelections.bigmodel` 读 `{kind:"team-coding-plan", organizationId, projectId}`（legacy `modelProviderFamilySelectedKeys.bigmodel="team-plan:builtin:bigmodel-coding-plan:{org}:{project}"` 回退与额度链 teamSelectionOf 同门，review A/D：仅写旧键的宿主两链口径不得分叉；未切团队 fail-closed 不发请求）→ ① `GET bigmodel.cn/api/biz/customer/getCustomerInfo`（裸业务 token）校验 org/project 存在 → ② `GET .../organization/{org}/projects/{project}/api_keys`（团队头 Bigmodel-Organization/Bigmodel-Project）找 `name==="zcode-team-api-key" && keyType===2`（缺条目不创建——创建属宿主 App 内切换行为；**密钥 ID 在条目的 `apiKey` 字段**——线上条目形状为 `apiKey, createTime, isHidden, keyType, lastUseTime, name, publicKey, secretKey, tokenType, usageScene, useApiKeyUserId, useUserName`，没有 `apiKeyId`——线上形状来自 issue #481 报告者的抓包，宿主源码 `project-access-token-client.ts`（`apiKeyId: key.data.apiKey`）与之吻合，维护者尚未用真实团队账号复核；旧实现要求 `apiKeyId`，团队密钥恒找不到、换发在本地就断掉；宿主 `ProjectAccessTokenClient` 同款读条目 `apiKey` 再拼 URL）→ ③ `POST api_keys/{apiKey}/access_tokens`（Bearer 业务 token，体 clientType/clientVersion；密钥 ID trim 后经 `encodeURIComponent` 拼接，`.` 与 `..` 是路径段保留写法——URL 规范化会吃掉上一级路径段——按没有团队密钥处理）换项目级短期 PAT（响应 `{enabled:true, accessToken, tokenType, expiresIn, expiresAt}`）。PAT 打与 individual GLr token 同一 messages 端点（宿主团队对话同链路）；响应形状复用换发信封解析（enabled/enable 双别名、accessToken/token 别名、expiresAt/expiresIn 记忆过期，缺省 1 小时、到期前 2 分钟内不复用 memo；fingerprint=OAuth+org+project；**`expiresAt` 是 10 位秒级时间戳**（issue #481 报告者抓包样本，`expiresIn` 同为秒），解析时 `< 1e12` 视为秒换成毫秒再与 `Date.now()` 比较——不换算则 memo 永不命中、每次增强重跑三步；离谱值按缺失处理（回落 `expiresIn` 或缺省 1 小时），否则 PAT 会被永久缓存：非有限值、换算后距今超过 7 天的 `expiresAt`，以及折算超过 7 天的 `expiresIn`；已过期的 `expiresAt` 原样保留，让 memo 落空去重换）。换发失败/形状不符/未切团队一律 kind `team_auth` 并带环节码（见下文契约 10；issue #481 前为 plan_auth）；三步共享 15s 预算与外部 signal，不重试。团队源不进「从宿主选择」同步公告列表（三步是异步链，同步门拿不到活凭据；默认模式增强不经该列表）。zai 团队未实测维持 planKeyOf 诚实尝试。

## 插件实现契约（model-puller）

1. **作用面**：仅 `fam==="bigmodel"` 的 PLAN_SOURCES 源（individual/team/start-plan）。zai 家族端点未实测，维持现状（OAuth 诚实尝试）。套餐模型列表与确认流探测的端点/凭据契约另见 [plan-model-list.md](plan-model-list.md)（2026-11-24 实测 Anthropic 网关拒 OAuth 登录令牌后，探测凭据序与本节对齐）。
2. **凭据解析序**（enhanceText 内，bigmodel 源）：v2 条目明文 key（`planEntryKeyOf`，兼容 3.18 宿主/报告者机器）→ GLr 换发 token（新）→ 均失败回 `plan_auth`（零网络 fail-fast 语义不变）。**OAuth 直连兜底从 bigmodel 源移除**（v344 起实测必败，#429 报告者机器的 1234 即此路径）。**团队源例外（issue #442）**：条目 key 与 GLr location 都属个人项目，团队源（PLAN_SOURCES `teamPat:true`）绝不用——凭据只走团队 PAT 三步换发（`planTeamPatOf`），未切团队/换发失败回 kind `team_auth` 并带环节码（契约 10，issue #481）。
3. **location 读取**：扫 credentials.json 键名（前缀 `project-key-location:v1:`），URL-decode 取 JSON 数组，匹配 `family==="bigmodel" && team==null && usageScene===1` 的首条；值过 `decryptValue` 解密（`enc:` 前缀结果一律作废，同 planTokenOf 纪律），`{organizationId, projectId, apiKeyId}` 三键非空字符串才可用。
4. **换发请求**：origin 取 location 键名还原值（校验限定 `bigmodel.cn` 及其子域）；`clientVersion` 取宿主 appVersion（本文件运行于 Electron 主进程，`require("electron").app.getVersion()` 直取，异常/测试环境省略该字段）；UA `ZCode`（同 enhance 既有头）；15s 超时、跟随 enhance 的外部 signal；**不重试**（enhance 自身已有二次尝试，换发失败直接 plan_auth，避免叠退避）。
5. **响应处理**：`code` 为 200/0（数字或字符串）且 `data.accessToken` 非空字符串才采信（`token` 为兼容别名，#432；`enable===false` 别名同拒，issue #442 团队端点同族形状）；`enabled===false`、404、401/403、其它形状一律按换发失败 → plan_auth（401/403 不细分为 auth：OAuth token 失效时用户重登后 location/token 都会换新，plan_auth + 重试语义已覆盖）。
6. **路由读取**：glob `<v2>/runtime/provider/<platformDir>/*/*/endpoint-*/zcode-builtin.json`（platformDir 以 `process.platform` 前缀匹配：win32→windows、darwin→darwin、linux→linux），版本段取可解析的最高 semver；解析 `config.providerConfigRules.providerRules` 中 `providerId===目标源` 条目的 `config.api.baseUrl`（stat stamp 缓存含 ino/dev，同 readTemplateRules 纪律）。baseUrl 收编家族官方域白名单（`bigmodel.cn`/`zcode.z.ai`/`z.ai` 及子域，https+后缀判定）——runtime 配置是同权限进程可写的宿主托管状态，白名单外一律拒绝回退表值（review D-1 纵深防御）。读不到（旧宿主/结构变化/白名单外）回退 PLAN_SOURCES.baseUrl 硬编码并照常尝试。
7. **内存纪律**：换发 token 只在内存；实例闭包 memo `{fingerprint, token, at}` TTL 10 分钟（fingerprint=OAuth token 摘要 + location 键名 + 信封串——键名或值任一变化即失效；实例级使热换重建天然换新 memo，无跨实例泄漏），enhance 的两次 attempt 复用同一 token；不落盘、不进日志/诊断/渲染端（渲染端只见最终 ok/kind）。resolveEnhanceHost 保持同步：仅当 memo 内有活 token 时对 GLr-only 源（无 v2 条目 key）返回 host——列表首次使用前不列，默认模式增强（主路径）不受影响，文档如实注明。
8. **fail-closed 矩阵**：无 location/解密失败/形状不符/家族外 location/契约外 team 形状 → plan_auth；换发网络失败/超时/非 2xx/`enabled:false`/响应 code 非 200|0 → plan_auth（静默无 log——GLr 失败路径零诊断输出，凭据零泄漏面）；v2 key 与 GLr 都不可用 → plan_auth。GLr 成功后真实 messages 调用的上游错误（含 1113→balance）走 #430 既有分类。
9. **兼容性**：3.18 宿主（v2 config.json 在）走 v2 key，零换发行为不变；3.19.x（config.json 无）走 GLr，恢复与宿主对等；纯 start-plan 账号在 zcode.z.ai + 换发 token 的真实可用性未实测（无纯 start-plan 测试账号），失败按上游错误/plan_auth 诚实呈现——这正是 #429 报告者场景的唯一可能修复路径（其主对话同链路可用）。
10. **团队链失败环节码（issue #481）**：`planTeamPatOfSolo` 返回 `{pat, fail, status}`——成功时 `pat` 非空；失败时 `pat` 为空串，`fail` 取固定枚举：`selection`（读不到宿主的团队套餐选择）、`token`（业务令牌不可用）、`customer_http`／`customer_mismatch`（返回里没有所选组织或项目）／`customer_shape`、`keys_http`／`keys_missing`（没有 `zcode-team-api-key` 且 `keyType===2` 且带 `apiKey` 的条目）／`keys_shape`、`pat_http`／`pat_shape`、`network`（超时或网络异常）；`*_http` 另带该步的 HTTP 状态。HTTP 200 的业务失败信封（没有 `organizations`／`data` 列表）归 `*_shape`，不算「团队不存在」或「密钥缺失」。`enhanceText` 据此回 `{ok:false, kind:"team_auth", reason, status?, error:"team credential exchange failed (<reason>[, HTTP <status>])"}`（`status` 仅 HTTP 类携带），主进程同时落一行日志 `team pat exchange failed: <reason>[ http <status>]`。环节码只含环节与性质：令牌、密钥 ID、组织/项目 ID、响应体一律不进回执与日志；用户取消不落日志、仍回 `cancelled`（不算失败），进门前外部 signal 已取消的调用同样如此。渲染端把环节码本地化成「团队凭据换发失败（第 N 步…）」；表外码工具栏回落 `error` 短语、设置页测试区回落通用失败文案（[prompt-enhance.md](prompt-enhance.md)）；旧渲染端读新 kind 落 `error` 英文短语。额度链 `ensureTeamPat` 的换发 URL 与 `expiresAt` 归一与本条同口径，改一处须两链同步。

## 测试矩阵（tests/model-puller-enhance.test.cjs）

- location 键扫描/URL-decode/家族与 team/usageScene 过滤（含干扰键负例）/解密信封/形状校验（各自独立红绿）。
- 团队三步换发（issue #442）：三步顺序与头形（裸 token 查存在性/团队头列 key/Bearer 换 PAT）；PAT 打 open.bigmodel.cn messages 双头；个人 GLr exchange 与 v2 条目 key 对团队源零调用；memo 到期前复用（三步只跑一轮）；fail-closed 矩阵（未切团队/空 org/非团队 kind/customer 404 或 org/project 不符/keys 失败或缺 zcode-team-api-key(keyType=2)/PAT 404 或 enabled:false → team_auth 零 messages，issue #481 起逐分支断言环节码、HTTP 状态，以及回执与日志里零凭据泄漏）；同夹具下 individual 源仍走自身 GLr location（回归）。
- 团队链线上形状（issue #481 报告者抓包）：密钥条目夹具与线上同形（密钥 ID 在 `apiKey`、无 `apiKeyId`，换发 URL 为 `api_keys/{apiKey}/access_tokens`）；只有 `apiKeyId` 的幽灵条目不被采信、零 `access_tokens` 请求；密钥 ID trim 后经 `encodeURIComponent` 进 URL，`.` 与 `..` 不被当成密钥 ID；秒级 `expiresAt` 的 memo 复用、毫秒 `expiresAt` 照常比较、短 TTL 的三种下发形态（秒级/毫秒/只带 `expiresIn`）都重换、离谱的过期值按缺失处理（JSON 文本 `1e400`、`1e308`、`1e15`、`9.99e13`、`5e11`、`1e13`；离谱的 `expiresIn` 回落缺省 1 小时，合理的几小时 `expiresIn` 照常生效）、已过期的 `expiresAt` 原样保留；memo 按团队选择与登录令牌指纹隔离（换团队或重新登录即重换）；外部取消（含进门前已取消）仍回 `cancelled` 且不落失败日志；盘上同时有个人条目 key 与个人 location 时团队链失败也不回退个人凭据；`error` 短语逐分支断言（旧渲染端兜底显示）。额度链 `tests/quota-team-plan.test.cjs` 同批锁定换发 URL 的真实密钥 ID（列表前另有同名族诱饵）、秒级 `expiresAt` 的缓存复用与 2 分钟提前量重签。
- 恶意 origin 矩阵（evil.com 及伪装形）零网络拒绝；runtime baseUrl 白名单外回退表值；异平台目录不生效；memo TTL 过期后同步门失效。
- 换发 200 → token 进 Authorization 打 runtime 权威端点（start-plan→zcode.z.ai 断言）。
- 换发 404/401/enabled:false/形状坏 → plan_auth 零后续请求。
- v2 条目 key 存在时不发换发请求（3.18 兼容）。
- memo：同 fingerprint 10 分钟内第二次 enhance 不再换发；fingerprint 变化即重换。

- OAuth 不再作为 bigmodel 兜底（无 location 且无 v2 key → 零网络 plan_auth）。
