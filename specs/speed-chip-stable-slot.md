# 速度格稳定占位与展示协调（生成速度 Chip）

## 目标与不变量

状态允许实时变化、文字允许更新、速度允许刷新。**速度格（`data-zu-key="speed"`）在同一个布局档位里所有格面同宽（v459，用户实报「上述状态变化时宽度不一致，还是有抖动」）：固定 `width:6.6em`**（14px 格字号 92.4px、12px 79.2px，即此前速度态 `60.5 t/s` 的宽度），不再随内容伸缩（v455 的内容自适应与 v456 的上限 `calc(38px + 4.8em)` 废除）；**右内边距为 0**（v459，用户指示「去除右侧的 padding」——腾出的 7px 给内容，带状态词的面不必变宽），**格与右侧分隔线之间的间隙 +10px**（v459，用户指示「右侧空隙再增加 10px」）。内容超过固定宽时标签收缩省略；**状态词与数值之间不画间隔点（v460，用户三选一裁定「宽度不变，去掉间隔点」）**，两字状态词加不超过 4 字符的计时完整显示（「思考 4:28」「执行 0.0s」）。**数值本体（`.zu-sp-val`，`flex:0 0 auto` 不收缩）常规面完整**；唯一例外是 >1h 长计时（`1:05:00` / `23:59:59`，标签已收缩到 0 仍放不下）数值尾被裁——14px 系统字体 ≤2px，11px 界面字号 + 宽字体（夹具 Verdana 栈）`1:05:00` 约 3px、`23:59:59` 约 11px，已知名单 `thinkDay` / `thinkHour` / `enThink`（v456「任何字号恒完整」靠的是上限 105px 的余量，固定宽后不再成立）。unit「t/s」在 9999.9/子代理长数值面允许裁尾几像素（dim 辅助色；14px 下 9999.9 约 4.6px、`代理×12 1286.5 t/s` 约 9.6px）。**任何情况下不推挤相邻格**（`overflow:hidden` 兜底）。覆盖默认、药丸、精简三主题（精简 chip 保持档位固定宽，见下）。

不变量：

- `zuBarSpeedView` 仍是状态的唯一判定者（八类 kind：subagent / toolgroup / skill / tool / thinking / estimate / avg / real），`text`/`cls`/`phase`/`band` 逐字保留并继续供 tooltip、无障碍全称与「···」菜单消费。展示层只读结构化字段（`kind`/`phase`/`nameText`/`activeCount`/`speedValue`/`elapsedMs`），**禁止解析 `text` 文案反推状态**。
- 速度十档（`TPS_BANDS`/`tpsBand`）阈值、类名、tooltip 档位说明不变；缩写值不参与分档。
- 真实 token / 速度 / 费用 / 时间统计口径不变；展示层的节流与防抖不写回任何数据。
- 折叠优先级（`zusage3.barPriority`、`zuBarFoldOrder`，speed rank=-1 排最后候选）不变；速度格不是折叠豁免项。
- tooltip 悬停中仍读最新真实视图（v224/perf 规则 4），不受格面节流影响。

## 根因（改造前，源码核对）

1. **DOM**：`<span class="it" data-zu-key="speed" tabindex="0">` = `[svg.ico]` + `<span class="zu-live <dim|档位类>[ zu-shimmer]">文本</span>`；精简主题为 `<span class="zu-tsb">` 内同一个 `.zu-live`（无图标）。
2. **外部宽度由内容决定**：`.zusage-root .zu-main>.it{flex:0 0 auto}` + `.zu-live{display:inline-flex}` + 条 `white-space:nowrap` → 格宽 = 图标 + 文本自然宽。`tabular-nums` 只保证同字符数等宽，挡不住「28.8→1286.5」「思考中…→子代理运行中 · 估 …」的字符数变化。
3. **整条重建**：`render()` 在 `h.s !== lastHtml` 时 `main.innerHTML = h.s`（数据帧、设置/主题变化、速度相位切换经 updateLive 慢路径）。
4. **原地改字**：updateLive 快路径（同相位且上一拍已 live）只写 `liveEl.innerHTML`/`className`（100ms 心跳 + store 通知，最高 10Hz）。
5. **tooltip 锚点**：`.it` 格元素（`__tip` 属性 + `tipFor`）；精简主题挂 `.zu-tsb`（`__zuT.buildTip`）；折叠后菜单项克隆格图标并抄 `__tip`。
6. **固有尺寸来源**：`.it` 的内容宽（`flex:0 0 auto`）、`.zu-live` 的 inline-flex 内容宽、药丸条 `width:max-content`。
7. **窄宽探针**：`track()` 每 ≥250ms 以 `measureKey = main.innerHTML + 字体…` 判断是否重测——离屏克隆 `.zu-main`（`width:max-content`）量 full/tight 两档自然宽，按 +24px 迟滞在 shrink 0/1/2 间切换。
8. **触发自动折叠的文本变化**：①速度格任何文字变化都改 `main.innerHTML` → 探针每 250ms 克隆重测，状态词长短可翻转 shrink 档；②shrink===2 时 `syncBarOverflow` 逐帧读 `scrollWidth`，速度格变宽跨过 `ov>1` 即触发折叠、变窄跨过 `ov≤1−24` 触发回展。
9. **三主题格式化**：默认与药丸共用 `html()` 与 updateLive；精简走 `syncTpsChip` 自拼文本（DB 回退为 `dbTps + " t/s"`，与条面 `(v%1?toFixed(1):String(v))` 不同款），aria-label 也不同（条面仅空面时写、chip 恒写）。
10. **额外重排**：是。10Hz 原地 `innerHTML` 写入使 `.it`→`.zu-main` 重排；探针重测随速度文字每 250ms 触发；药丸逐帧 `getBoundingClientRect().width` 算居中，宽度一变整条左右挪。

## 展示模型（纯函数 `zuSpeedFace`，07 分片实例级渲染助手区）

展示模型与状态机分片分离：`zuBarSpeedView` 留在 02 分片（只追加数值字段），`zuSpeedFace`/`zuSpTime`/`zuSpNum` 与格面/图标/全称助手放在 07 分片的实例级渲染助手区（`ttEsc` 到 `stubFor` 之间）——`html()` 的 VM 切片夹具统一按这个区间取助手，展示函数放模块级会让布局类回归整体断链；协调器阈值 `ZU_SPEED_DISP_MS` 仍是模块级（08 按名引用，全源夹具按名置 0）。

`zuBarSpeedView` 追加数值字段 `elapsedMs`（工具/工具组/Skill = 当前时刻 − 起始时刻，缺起始时刻为 null；思考 = 已用毫秒）。`zuSpeedFace(view, autoWidth)` 返回 `{label, value, unit}`（`autoWidth` 只由精简 chip 传 `true`：容器按内容定宽，「长计时面不出状态词」不适用，见下）：

**长计时面（v464，用户实报截图「思... 1:22:02」）**：计时满 1 小时起，紧凑时间的写法从 `59:59`（5 位）变成 `1:22:02`（7 位）或 `1天3时`，数值自然宽从约 39.7px 涨到 45.7~52.8px（14px 格字号，真实条隐藏克隆实测）。固定宽 6.6em（92.4px）扣掉图标 14px 与两处 5px 间隙后，标签 + 数值只有 68.4px，两字状态词要 28px——数值不许被裁（`flex:0 0 auto`），能被挤的只有状态词（`flex:0 1 auto` + 省略号），于是被挤成「思...」。所以带计时的四种面（`thinking`、`toolgroup`、`skill`、`tool`）在**计时 ≥ 1 小时（`elapsedMs ≥ 3600000`）时不显示文字标签，只留图标 + 时间**：图标已经说明状态（动效脑 = 思考、扳手 = 工具），全称（`aria-label`、「···」菜单、tooltip）不变。格宽不变（仍 `6.6em`），数字紧跟图标，右侧余约 12~21px；不足 1 小时不变。换写法解决不了（`1h22m` 47.2px、`1天3时` 45.7px 同样挤掉标签）。触发场景 = 长任务回合（思考计时跟着累加；用户那次是跑了 82 分钟的一轮）。英文同理（`Think` 等标签同样隐藏）。**只作用于固定宽的状态条速度格**：精简 chip（`.zu-tsb`）与速度格共用展示模型，但它按内容定宽——中等档 `9.7em` 本来就是按「Think 23:59:59」标定的，状态词放得下。首版漏了这一点：chip 满 1 小时也只剩时间、右侧空出一大块，部署当天补上例外（`zuSpeedFace(view, autoWidth)`，11 分片 chip 调用传 `true`）。不在本条范围：英文较长的状态词（`Think` 37px）配 `59:59` 在默认条放不下，是既有问题。

数值：`<10000` 保持既有精度（估算一位小数、完成态整数不带小数）；`≥10000` 起缩写，k/M/B/T 逐级、进位不跨档（`10.0k`、`1.0M`、`1.0B`、`2.5T`；仅展示层，tooltip 读真实视图保留精确值，缩写值不参与分档）。非有限/负值由 `zuBarSpeedView`/回退分支既有策略拒绝，不伪造 0。

## 占位（CSS 驱动：全部格面固定宽，零新增测量，v459）

格 DOM：`.it.zu-speed` = `[svg.ico]` + `.zu-live` = `.zu-sp-label`（`flex:0 1 auto; min-width:0; ellipsis`；空标签不参与布局）+ `.zu-sp-val`（`flex:0 0 auto; nowrap`）+ `.zu-sp-unit`（可无）。数字与单位仍是零空格两 item，间距由 gap 提供（v326 机制延续）。格 `box-sizing:border-box; overflow:hidden`（兜底裁切，绝不推邻格）。

宽度规则（v459）只有一条：`width:6.6em`（border-box，随格字号缩放）——**思考、工具、子代理、生成中估算、完成态、数据库回退全部同宽**；没有下限/上限区间（v455/v456 的 `min-width`/`max-width` 废除）。`6.6em` 即 v453 为速度态标定的宽度（「`250.0 t/s`」），14px 格字号 92.4px、12px 79.2px。配套三条间距规则，都由用户 2026-11-24 指示：

- **右内边距 0**（`:not([data-zu-speed-min='1'])` 的格面，v459）：内容可以从格左缘排到右缘。极窄档（仅图标）保留所在档位的两侧内边距（图标从左内边距之后起排，不居中——v449 起各档统一靠左；2026-11-24 实机克隆条实测：宽裕档左 7px、右 17.5px，中等/紧张档左 4px、右 17px）。
- **左内边距 0（v462，用户指示「左侧的 padding 也去掉」）**：默认条里图标贴格左缘，也就是状态条左缘（默认条 `.zu-in` 没有横向内边距）。宽度不变（仍 `6.6em`、右侧间隙 10px），腾出的 7px 给内容：带状态词的面 `.zu-live` 可用宽从 66.4px 变 73.4px（14px 格字号）。选择器 `:not(.zu-pill) .it.zu-speed:not([data-zu-speed-min='1'])`。**药丸不做**：药丸有底色与 12px 圆角，图标靠左内边距（宽裕 7px、中等/紧张 4px）离开边缘；也没有改成「左内边距换左外边距」——药丸中等/紧张档自带 4px 左内边距，外边距抵消不了，会多推 7px。精简 chip `.zu-tsb` 不是这个元素，不动。
- **状态词与数值之间不画间隔点（v460）**：v446 起宽裕档用「 · 」隔开状态词与数值（连内边距占 16px，两字标签自然宽 44px），中等/紧张档与精简 chip 本就不画。v459 固定宽 92.4px 里，带数值的两字状态词因此全部被省略成「思…」「执…」；实测要保留间隔点并让「思考 · 4:28」完整，得放宽到约 107px（速度态右空白 +15px）。用户第七轮在「放宽 12~15px 保留间隔点」与「宽度不变去掉间隔点」之间选了后者。去掉后标签与数值之间只剩 `.zu-live` 的 5px 间距，两字状态词加不超过 4 字符的计时都完整：`执行 0.0s` 余 3.2px、`思考 4:28` 余 1.7px、`执行 59s` 余 7.7px（14px 格字号实测）；更长的才省略——5 字符计时 `查阅 12:34`、`1:05:00`、带数值与单位的 `代理 28.8 t/s`、英文 `Think`（v462 默认条再去掉左内边距后，5 字符计时在默认条宽裕/中等档也完整，见下条与验证证据；药丸仍省略）。无计时（宿主未写 `startedAt`）时只剩状态词，不再有悬空的间隔点。

精简主题 `.zu-tsb` 挂在宿主工具行的前导区（`[data-composer-leading-content]`，与宿主自己的按钮同区、不收缩），没有窄宽状态机。宿主放不下时会逐级压缩**它自己的按钮**（宿主 `useComposerToolbarFit`：先收扩展插槽，再依次收 Computer/模式/Plan/思考的文字，最后把模型名收成图标）——chip 的宽度直接决定宿主按钮被压多狠。改动前 chip 宽度随文字变，宿主按钮会在一轮对话里跟着来回压缩/展开（目标 §1.1 第 7 条）。现在 chip 分三档，类名与药丸档位同名（`zu-speed-mid` / `zu-speed-tight`），规则只作用于 `.zu-tsb`：

| 档位 | 宽度（13px 基准） | 内容 | 标定（六种字体栈下的最大自然宽） |
|---|---|---|---|
| 宽裕 | `12.4em`（161px） | 标签 + 数值 + 单位 | 「代理×12 1286.5 t/s」≈155px（Verdana；157.8px 为带 `≈` 时的标定） |
| 中等 | `9.7em`（126px） | 标签 + 数值（去单位） | 「Think 23:59:59」123.5px（Verdana） |
| 紧张 | `6.6em`（86px） | 仅数值（靠左） | 「23:59:59」82.9px（Verdana） |

chip 无图标，故没有「仅图标」的最窄档；界面字号 14px 时三档落在目标的宽裕 / 中等 / 紧张区间内。chip 内排布与条面同规则：标签 + 数值 + 单位紧凑成组、靠左，剩余空间留在 chip 右侧；完成态无标签时数值从 chip 左缘起排。

档位由 `zuTsbTierSync`（11 分片，`syncTpsChip` 末尾调用，至多每 250ms 量一次——条内窄宽状态机是逐帧 60Hz）选择，**只由宿主工具行的真实空间决定、与 chip 自身宽度无关**：空位 = 前导区可用宽度（`[data-composer-leading-actions]`，宿主 `flex:1`）− 同区其它内容（宿主按钮 + 本插件其它 chip）。

- **放不下**（空位小于当前档宽度）：同一次判定里直接降到装得下的那一档（空位与自身宽度无关，同拍算到底是安全的）。挂载当拍即量（chip 插入后、宿主的 ResizeObserver 之前），空间不够时 chip 已先降档，宿主不必压缩。
- **宿主已在压缩自己的按钮**（`data-composer-compact` / `composerProviderCompact` / `composerModelIcon`）：再让一档，一次只让一档——插件 chip 先让位，不拿宿主按钮换宽度。
- **升档**：距上一次降档或见到宿主压缩 ≥2 秒（静默期），且空位 ≥ 上一档宽度 + `FOLD_HYS`（24px）；一次一档。
- **不振荡的依据**：①对宿主——因宿主压缩而降档后，宿主若因此展开，空位必然小于刚让出的那一档，升档条件不成立。②对同区的 Git / 系统状态 chip——它们按对称公式（`gitMeasureAvail`：空位 = 前导区 − 同区其它内容）各自升降、收缩即时。两边同一拍都升档会撑破一行，此时本 chip 先降回去并进入 2 秒静默期，下一轮只有一边先升、另一边发现空间不够而停住。
- 窗口拖窄的过渡期：宿主的 ResizeObserver 在当帧先压缩，chip 最迟 250ms 后让位，宿主随后帧展开——宿主按钮的压缩只闪一下。
- 找不到宿主前导区（其它宿主/旧布局）时不分档，保持宽裕档；前导区尚无尺寸（窗口最小化、后台分栏）时不判定。宿主的单行输入框（`iconOnly`）恒处于压缩态，chip 恒在最窄档。
- 旧值 `10.5em`（136.5px）是单一固定宽：对「代理×12 1286.5 t/s」越界 7.3px（标签被裁成「代理×…」）；空闲时比改动前（约 54px）多占约 80px。真实宿主实测（1200px 窗口、单分栏、额度 chip 开）：前导区留给 chip 的空位 358px，窗口窄于约 1000px 时固定 136px 会迫使宿主压缩按钮。

- 估算不带 `≈` 前缀（v452）、也不带「生成」标签（v454）：生成中只靠流光动画区分，数值本身不带标记；子代理面自 v461 起是「子·X」（见上「子代理面」一条）。各档一致。
- **图标与文字贴近（2026-11-24 用户实报修订）**：图标、标签、数值、单位紧凑成组，从格左缘起排，剩余空间留在格尾（右侧）——格没有底色与边框，留白不可见；v459 起全部格面固定宽，格内剩余空间 = 固定宽 − 内容（速度态 4~14px，带状态词面 0px）。标签 `flex:0 1 auto`：只在内容装不下时收缩省略，不再吃掉剩余空间；空标签（完成态）`display:none`，「闪电 + 数值 + 单位」与改造前同观感。各档统一靠左，窄档与药丸紧张档不再 `justify-content:flex-end`。

- 流光（`zu-shimmer`）类串不变，仍由包装层 `.zu-live.zu-shimmer` 既有规则承载（真实宿主实测：flex 子项与标签 overflow:hidden 下渐变文字正常渲染）。
- 档位切换只由窄宽状态机与折叠段驱动；迟滞沿用既有 +24px / `FOLD_HYS`，不新增阈值。

## 折叠段与探针（specs/statusbar-layout.md 的增量）

- 折叠循环在轮到 speed 候选时先降「极窄」（写 `data-zu-speed-min="1"`）再判溢出，仍溢出才折叠。极窄**不在回展分支里解除**：每轮重算开头先把上一轮的折叠集与极窄档整体清空（既有「从头重算」起手式），变宽后自然回到完整宽。同轮内「先试解除极窄、富余够就解除」是不可达分支——降极窄的前提是完整宽溢出，解除后「完整宽装得下且富余 ≥24px」与之矛盾（变异验证暴露的等价死代码，已删）。离开 shrink 2 / 非 default 主题时随折叠集一并清除该属性。
- 离屏探针克隆除剥 `data-zu-folded` 外同时剥 `data-zu-speed-min`（否则同一正反馈震荡环复现）。
- `measureKey` 剔除速度格面内容（`.zu-live` 内文本）与格上的全称属性（`aria-label` / `data-zu-full`，随状态与计时变化）——占位固定后它们都不影响自然宽，计时/速度走字与状态切换不再触发整条克隆重测；其余格与字体签名照旧。
- 折叠菜单项与「···」实时值读 `data-zu-full`（无该属性回退 `textContent`）：速度项显示完整状态词（如 `查阅·执行中 3.2s`），固定宽度不作用于菜单行；点击仍弹原速度 tooltip。
- **富余判据改用真实内容宽（本次发现的既有缺陷）**：`.zu-main` 用 `space-between` 摊开子项，`scrollWidth` 以 `clientWidth` 为下限——非溢出态恒等于 `clientWidth`（宿主实测：内容 151px 装进 300px 容器 `scrollWidth=300`）。旧判据 `scrollWidth ≤ clientWidth + 1 − FOLD_HYS` 因此从未成立：折叠循环每轮多折一格，折叠态的逐帧回展触发器是死分支。现由 `zuBarContentWidth()` 按可见子项 rect 宽度和（加 `.zu-main` 的 1px gap）计内容宽，可小于容器；折叠重算、重算尾部的触发器基线、以及「已折叠且未溢出」时的逐帧探测三处同用它（基线与逐帧必须同口径，否则每帧重算）。重算门口同时记 `.zu-main` 自身宽度（折叠判据的容器是它）。未折叠态的溢出探测与 `zu-clip` 仍读 `scrollWidth`，逐帧常规路径不新增布局读取。行为变化：①折叠后装得下且富余 ≥24px 时不再多折一格；②已折叠态失去富余（内容变宽或容器变窄）会触发重算并继续折叠——默认主题里「全折仍溢出→横滚+渐隐」因此不再可达（重算会吸收溢出），`zu-clip` 渐隐实际只服务药丸与瞬时态；旧夹具靠「钳 `.zu-main` 宽度制造溢出」的用例已改为验证「速度格先降极窄、再折叠、再恢复」的真实序列。

## 展示协调器（实例级 `zuSpDispPick`，仅管展示时机）

无定时器：在既有 100ms 心跳 / store 通知到达时按时间戳裁决，实例闭包状态随实例销毁；按「会话 sid + 轮 id」身份隔离，不进 localStorage、不进快照。

输入真实视图 `view`，输出展示视图 `dview`（形状同 view；格面只读 dview，tooltip 只读 view）。

- **立即展示（硬边界，优先于一切保持）**：身份变化（会话/轮）；`view` 为空或上一展示为空（数据源切换 live↔回退↔无）；`view.kind ∈ {avg, real}`（会话结束的最终速度）或上一展示为最终态。
- **状态切换（两边都是运行态）**：候选状态须连续保持 ≥180ms 才上屏；态键含同态内的「面」身份（工具名/工具组类别/技能名）——同类工具直接换手（Read→Bash、查阅→终端、换技能）同样要过防抖，极短的新工具不闪现；真实状态回到已展示态即作废候选（A→B→A 抖动时 B 不得累积防抖时长，候选期内的同态节流早退同样作废）；若当前展示是 thinking/estimate（非关键中间态）且上屏不足 400ms 则继续保持——工具类状态（tool/toolgroup/skill/subagent）不被最短显示挽留，工具结束后不会 lingering「执行中」超过一个防抖窗。
- **同态数值刷新**：estimate 与 subagent 的数值+档位色取自同一次真实视图快照，≥600ms 才换一次（初入状态立即取当前值）；子代理数量变化立即反映。
- **计时节流（`time`，1000ms）**：只管同一状态内的耗时文本刷新——首拍即取当前真实耗时，其后每秒换一次；无值→有值（宿主 `inputStreaming` 行不写 `startedAt`，执行后才有）立即；状态进出（工具结束、报错、桥断开）不受它约束；耗时始终取真实时间戳之差，不重新起算。
- **颜色稳定**：灰（工具/思考/无速率子代理）↔ 档位色互换后至少 400ms 不再变色；同色切换（如工具→工具组）不受约束；硬边界优先。同态内的档位色随数值节流一起换（`num ≥ color`，测试锁定）。
- 常量集中在模块级 `ZU_SPEED_DISP_MS = { debounce: 180, minShow: 400, num: 600, color: 400, time: 1000 }`（测试夹具可置 0 以保持既有「立即展示」断言）。
- **防抖边界（硬边界优先于一切保持）**，均有真实阈值的测试（`tests/overlay-bridge.test.cjs` 走完整 turn-stats.js + overlay.js）：
  - 桥断开：会话存储关闭（`getState()` 读到 null）→ 心跳探活当拍解绑、估算值不残留；存储静默不再推送 → 估算值随内核**既有**的 2 秒样本陈旧规则失效，协调器只再加最多 180ms 防抖（不加第二个 2 秒判定）。
  - 工具报错：内核只认 `inputStreaming/pendingApproval/running` 三种运行中状态，工具一出错即算结束，速度格只受 180ms 防抖约束（不被计时节流/最短显示/颜色稳定挽留）；整轮 `failed` 属最终态，当拍上屏。状态条的工具错误徽标（`.eb`）走数据库快照直渲染，不经协调器。
  - 数据库回退不冒充实时：面与完成态同款（无状态词，v452）、无流光，全称写明「最近一段」。
  - 子代理全部完成（子代理态→其它态）只受防抖约束，不被 600ms 数值节流挽留。
  - 协调器无定时器、不读 store、无在途异步状态；展示缓存按实例与「会话 sid + 轮 id」隔离。
- **状态序列 `思考 → 工具 → 思考 → 工具 → 生成 → 工具 → 生成完成`**：各态持续 ≥600ms 时七态按序全部上屏（图标与文字成对切换，完成态当拍）；两个 60ms 的极短工具被防抖吞掉、图标不跟着切；300ms 的工具照常显示（不隐藏有实际意义的工具执行状态）。
- 相位不变的状态切换只换 `.zu-live` 内容，标签文字变化时对标签播 120ms 透明度过渡（`Element.animate`，缺位静默跳过）；数值走字不播。

## 相位切换的原地换图标

updateLive 在「上一拍已 live 且本拍仍有真实视图」时一律走原地路径：相位变了只重写本格内容（图标 + 面）并重挂 `liveEl`，不再整条 `render`（此前每次思考↔工具↔生成都重建整条 `.zu-main`，重启呼吸灯/红点动画并触发探针重测）。找不到格元素（VM 字符串回放夹具）时回退整条渲染。live↔回退↔无数据的结构切换仍整条渲染。

## 无障碍

- 两处全称来源不同：`aria-label` = 「生成速度 」+ **展示视图**的全称（与格面同节奏：数值 ≤1.7Hz、计时 1Hz，高频速度更新不触发重复播报，内容被省略/精简时读屏仍得全文）；`data-zu-full`（「···」菜单的实时值）= **真实视图**的全称（节流窗内领先于格面，菜单值保持最新）。
- 速度格不接入 `ariaLive` 播报区、自身不带 `aria-live`（真实 DOM 断言）。
- 键盘聚焦（`tabindex="0"`）与 tooltip 打开路径不变。

## 性能预算

- 100ms 心跳内新增工作 = 一次纯函数格式化与时间戳比较；未变化不写 DOM（既有 `innerHTML` 幂等比较保留）。
- 数值节流后原地 DOM 写入频率 ≤ ~1.7Hz（估算态）；计时态随文本变化。
- 状态条（默认 / 药丸）不新增 interval、事件监听与布局读取；探针重测因 `measureKey` 剔除速度面而减少。
- 精简 chip 的档位判定是唯一的常规新增读取：只在精简样式下、至多每 250ms 一次，每次 3 个矩形 + 1 次属性选择器查询 + 1 次计算样式；挂在既有心跳调用的 `syncTpsChip` 末尾，无定时器、无监听器。
- 实测（2026-11-24）：协调器每次裁决约 0.95µs（Node VM 微基准，八种状态轮转），10Hz 下每秒约 0.01ms；精简 chip 档位判定的一组读数在真实宿主工具行上每次约 0.003ms（两次读数之间 DOM 无改动的干净路径），4Hz 下每秒约 0.01ms。
- 无障碍实测（真实浏览器）：状态条速度格的三种状态图标都带 `aria-hidden="true"`（装饰，含义由格面文字与 `aria-label` 承载）；速度格与精简 chip 都可键盘聚焦（`tabIndex` 0）且带完整 `aria-label`；精简 chip 不带图标。

## 验收场景

1. 八态逐一：格面 label/value/unit、全称、图标、档位类与表格一致；zh/en 两套。
2. 数字稳定性：`9.9→10.0→100.0→1000.0→9999.9→10000`（缩写 `10.0k`）、`1999.9→2000.0`；非有限/负值不渲染为 0。
3. 协调器：防抖窗内的短命状态不上屏；thinking/estimate 最短显示；颜色稳定 400ms（同色切换不受约束、硬边界优先）；最终态/身份切换/数据源切换立即；数值与颜色同快照；子代理数量减少立即；计时文本每秒一换（首拍取真实耗时、无值→有值立即）；同类换手过防抖；阈值常量 180/400/600/400/1000。
4. 折叠段：速度格先降极窄再折叠；每轮开头清空上一轮折叠与极窄；探针对 `data-zu-speed-min` 不敏感；`measureKey` 不含速度面。
5. 菜单与 tooltip：折叠后菜单项显示全称并随拍更新；tooltip 读真实视图不被节流。
6. 原地换图标：相位切换后图标、面、`__tip`、焦点与锚点保持。
7. 实机：真实宿主内量三主题各档宽度恒定（状态切换前后逐格 rect 一致）、深浅主题、窄窗四档、Windows 实机待校准（见下「验证证据」）。两种量法，工具都是 `tests/speed-slot-live-probe.py`：
   - 默认模式把全部状态面逐档量一遍（静态，不需要对话）。
   - `--watch N` 在真实对话进行时持续观察 N 秒：每 100ms 读一次真实速度格，按**与速度格自身宽度无关**的布局签名（档位类、最窄标记、格字号、条父元素宽度、窗口内宽、界面字号、像素比、面类别）归组，同一格面内宽度必须恒定、数值不越界；跨格面同宽由默认模式逐面核对（v459：同一档位全部状态面宽度必须相等）。同时报告格面切换序列、各态停留时长下界、只采到一拍的格面数、同可用宽度下的档位来回次数（来回过密只提示，需人工判断）。没有采到可量样本、或格面从未变化时退出码 3，不算通过。
8. 防抖边界：桥断开（存储关闭/静默）、工具报错、整轮失败、数据库回退不冒充实时、子代理全部完成、无定时器（`overlay-bridge` §7.3 系列 + `overlay-speed-slot`）。
9. 真实浏览器走完整数据链（`tests/overlay-pill-theme.test.cjs` 的 `speed slot through the live data chain`：伪造会话 store → turn-stats.js → `zuBarSpeedView` → 协调器 → `updateLive` → 真实布局，生产阈值、真实节奏）：默认宽档 / 右对齐 / 默认最窄档 / 药丸四种布局下，`思考 → 生成 → 读取 → 生成 → 完成` 加三次数值变化，逐格面核对**格宽 = `6.6em × 格字号`（全部格面同宽，v459）**、带状态词的面里**两字状态词未被省略**（标签 `scrollWidth ≤ clientWidth`，v460：间隔点去掉后「思考 + 计时」「读取 + 计时」都完整；窄档标签本就隐藏，不核对）、图标盒（脑/扳手/闪电）不变形且贴左、**数值本体不越出速度格**、布局档位全程不变、**邻格矩形全程不动**（右对齐时最右格不动；药丸始终居中）；图标与文字相邻（标签从文字盒左缘起排、数值紧跟标签，完成态无标签时数值紧跟图标；最窄档各态数值都紧跟图标），同一标签下数值左缘不随位数变化；工具错误徽标当拍出现且窄档仍可见；`aria-label` 数值与格面一致、节流窗内菜单全称领先于格面。
