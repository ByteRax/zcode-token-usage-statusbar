# 模型拉取确认与配置补全

## 产品规则

- 「⚡ 拉取模型」仍由用户在宿主模型设置中主动触发；模型列表拉取不等于连通性验证。
- 「确认添加并保存」对不超过 24 个勾选模型执行连通性探测，同批最多并发 4 个。检测/保存期间禁用确认和选择操作，避免重复批次；已通过模型不重复请求，已失败模型可由用户逐项重新勾选后强制保存。超过上限不自动批量请求。
- 有配置修复、补全说明或工具历史警告时，检测完成后保留弹窗供用户查看，再次确认才添加模型；后续检测失败也不得隐藏已经发生的配置写回。
- 探测使用当前供应商的实际协议与 Base URL。OpenAI Chat Completions、Responses 不隐式追加 `/v1`；Anthropic Messages 沿用宿主路径归一化。
- OpenAI 路径错误时，仅在相邻的添加或移除 `/v1` 路径通过探测后，才允许原子写回供应商 Base URL，并在弹窗披露。不能以探测失败为由猜测写入。
- 最低思考档位按宿主辅助调用语义验证；只有上游接受的档位才可补写。带自定义映射的规格不按内置映射猜测覆盖。
- 能力元数据优先采用供应商证据，其次采用目录匹配证据。同名目录存在歧义时，只采纳所有命中项一致的字段。主动能力探测仅适用于确认流中的 Chat Completions，不能覆盖已明确配置的能力叶子。
- 已添加模型可补齐有元数据依据、但尚未配置的上下文窗口与最大输出规格；不覆盖已有数值或自定义映射。
- 工具历史探测只提供兼容性警告，不改写工具能力开关；超时、网络、服务端故障不能当作通道确定性缺陷。

## 状态所有者与接口

- 渲染进程拥有弹窗、选择、探测展示和强制保存状态；关闭弹窗或实例销毁后，迟到结果不得继续触发保存。
- 主进程 `model-puller.cjs` 拥有凭据、拉取会话缓存、同供应商路径修复单飞和配置写闸；渲染端仅提供供应商 ID、模型 ID 与能力探测开关，不能提供任意配置对象。
- `model-pull-probe` 请求负载为 `{providerId, model, caps}`，外层沿用桥接的 `action` / `requestId`；`caps === true` 才请求附加能力检测。结果携带连通性、耗时、分类原因及经脱敏的修复/能力/规格/警告说明。
- 主桥仅在合法本地窗口请求路径中分派探测。旧主进程不认识动作时，渲染端回退到原有保存流程。
- 凭据只在主进程内存与目标供应商请求中使用；不跟随重定向向其他域发送，不回传凭据或原始敏感响应。套餐源 token 的解密与宿主凭据代际见 [host-credential-generations.md](host-credential-generations.md)。
- 配置写回重新读取最新配置，保留未知键、用户显式值及其它供应商；同目录备份和原子替换。探测期间协议、Base URL、凭据变化或模块释放时，停止旧探测的后续请求与写入；档位写回还须比较探测前后的目标规格，保留在途用户编辑。拉取缓存绑定供应商配置身份，不跨换源复用；成功的同域路径修复可迁移同一份拉取缓存。
- 同供应商可共享成功的路径修复；一个模型的候选失败不能否决其它模型。已存在自定义思考映射时不猜测其 wire 值；工具历史的鉴权失败、限流和暂态错误不构成不兼容证据。
- 单模型确认流总预算不超过渲染端 90 秒兜底；关闭弹窗清理本地等待定时器，不把取消界面误称已取消所有在途供应商请求。
- 本功能的主动探测可能消耗供应商额度；不启动后台周期探测、不影响 CLI/MCP 查询协议。

## 验收场景

1. 正常模型探测通过后保存；部分失败自动取消失败项勾选、弹窗保持打开；重新勾选失败项可明确强制保存。
2. 两种 OpenAI 协议均请求宿主实际路径；缺失或多余 `/v1` 仅在候选成功后写回，同供应商并发只执行一次路径修复。
3. 无效密钥、重定向、超时、失败响应和供应商变更均不能导致越域泄露或无依据配置写入；错误文本脱敏。
4. 最低思考档位被拒绝时，只写入验证通过的接受集；自定义映射、并发用户编辑不被覆盖。
5. 能力探测不覆盖显式 `false`，不把缺证据写成真；工具历史警告不把模型改为不支持工具。
6. 目录证据晚到时，已添加模型补齐缺失规格；已有上限和映射保持原样。
7. 关窗、切换供应商、实例销毁与旧主桥降级路径不误保存；所有请求超时定时器结算后及时释放。
8. 根产物与插件副本一致；`inject-main.cjs` 是冷文件，新动作需已部署的主桥在完全重启后生效。
