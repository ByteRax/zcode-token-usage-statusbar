# 模型明细「平均速度」列

## 产品规则

1. 本轮 / 会话累计 / 今日合计 / 项目累计（当前项目 + 「全部项目」模式的模型明细）/ 子代理统一浮层的「模型明细」表，以及精简摘要（速度 chip tooltip 的 `modelsBlock` 行式明细），每行新增「平均速度」列，展示该模型在对应范围内的平均生成速度。项目累计「全部项目」模式下的「项目明细」表按项目聚合，不加此列。
2. 列序为 **模型 | Token 用量↓ | 请求次数 | 平均速度 | 预估费用**；本轮/会话/今日/项目累计模型的预估费用列随 `state.cost` 开关收起（收起后为四列），**子代理统一浮层的模型表费用列常驻、关时单元格显 `—` 不收列**（既有行为，v375 前即如此）。表头文案 `模型/Model`、`平均速度/Avg speed`，值形如 `123.4 t/s`（`toFixed(1)`，t/s 语言中立），非 number 或 ≤0 显 `—`，不显假 0。单元格纯文本（`ttEsc` 转义）——Chromium 表格内在宽度计算遇 inline-block 会断行、`white-space:nowrap` 压不住，VM/stub 测不出，改表格布局须真浏览器验证。不使用 `TPS_BANDS` 色块。
3. 口径 = 项目唯一「平均」口径：`Σ有效输出 ÷ Σ有效生成窗口`，即 `usage_stats.row_gen_ms` 生成窗口 + 200ms–1h 有效段门控，含「首块即落章」`covers` 例外，复用 `zusage._rated_tps`（1 位小数）。与各统计卡 KPI「平均输出速度」同口径、同数值。不采用各请求 t/s 的算术平均。
4. **数据源集合按卡而异**，「与 KPI 同值」靠从同一处 `_turn_rate` 调用顺带累加保证，而非统一过滤条件：会话 / 今日 / 当前项目 / 全部项目 = `main_turn`（`query_source is null or 'main_turn'`）；子代理 = `query_source in ('subagent','workflow_child')`；本轮 = 不过滤 `query_source`（与本轮 `_turn_rate` 调用一致）。逐模型分量只在对应卡的速度聚合循环里累加，不在明细查询里另算。
5. 快照字段：每个模型对象新增可选 `avg_tps`（number）。仅进桌面快照链（`zusage.serve` 常驻 + 桌面一次性 json），与 `speed_history` / `all_projects` 同款门控；CLI 文本报表、MCP、`/usage`、hook stdout 契约不变。旧快照 / 远端旧帧 / 旧主进程缺字段时渲染端判 0/非 number 显 `—`，不冒用范围级 `avg_tps`。
6. 明细行集（全部 `completed` 行）与速度行集（各卡按规则 4 过滤）不同：仅含辅助/无有效速度段的模型，其 `avg_tps` 为 0、显示 `—`。这是「平均速度只按有效生成段计」的既有语义，不是缺陷。
7. 缓存策略（每范围单一携带结构，perf-lag-reduction.md 规则 8/13 的延伸）：会话 `avg_tps` 缓存值由标量改为 `{tps, per_model}`，今日把 `todayrate` / `todaydetail` 两个缓存键合并为单一 `todaydetail` 条目（含 `tps`/`models`/`cost`），KPI 与模型明细读同一份缓存结果。缓存命中帧同样拿得到 `per_model`，零新增全库扫描；水位续用与 2s TTL 语义不变。`_cached_agg` 的 `(key, fn)` 二参签名不变，连接经 `_WmFn` 携带；合并后 `_AGG_CACHE` 稳态键数从 5 降为 4（`scan` / `provfbk` / `today` / `todaydetail`），容量守卫不变。

## 验收场景

1. 同一会话有 A/B 两模型、各含有效段与无效段（缺首字 / 窗口超界），A/B 的 `avg_tps` = 各自 `Σ有效output ÷ Σ有效gen_ms`，且与会话卡 KPI「平均输出速度」在仅单模型有效时相等。
2. 子代理汇总与单项任务页的模型明细 `avg_tps`，与各自 `rate_avg` / `tps_avg` 在单模型场景相等；多模型时各模型值之和按窗口加权等于汇总值。
3. 关闭预估费用开关，模型明细表从五列收为四列，平均速度列仍在；重开恢复。
4. 旧快照（模型对象无 `avg_tps`）五列表的平均速度单元格显 `—`，不报错、不冒用 KPI 速度。
5. 长模型名 + 五列（含子代理表）在 450px 紧凑卡与窄窗下不破版、不横滚；真浏览器（内置浏览器/CDP）验证，VM/stub 不作为布局证据。
6. 缓存命中帧（水位未变、TTL 内）与重算帧的模型 `avg_tps` 一致；水位变化后重算，数值随新请求更新。
