# 宿主凭据代际与取钥

## 产品规则

- 内置套餐额度、ZCode Start Plan、重置卡与套餐源「拉取模型」都要用宿主 `credentials.json` 里的登录凭据。凭据值有三种形态：无前缀明文、`enc:v1:`、`enc:v2:`（宿主 3.18.0 起）；其它 `enc:*` 代际一律视为解不开。
- 解不开就是没有凭据：对应数据源按「未配置（解密失败）」降级，不发任何请求。任何情况下都不得把仍带 `enc:` 前缀的值当作 token 外发。
- `enc:v2:<os|env>:<keyId>:<payload>` 的密钥来源由条目自身声明：
  - `os`：密钥在系统钥匙串。插件主进程模块运行在宿主进程内，经宿主自带的钥匙串模块读取，与宿主自身的读取方式相同；不调用外部命令，不修改钥匙串条目的访问控制。
  - `env`：宿主 managed secret，来源序与宿主一致：`ZCODE_CREDENTIAL_SECRET`，其次 `ZCODE_CREDENTIAL_SECRET_FILE`（两者同时配置按不可用），最后是凭据同目录的 `credential-secret`。
- 取到的密钥必须与条目的 keyId 相符才用于解密。插件按条目声明的来源取钥，不像宿主那样再要求该来源等于当前环境解析出的来源，同目录文件也不以「没有钥匙串标记」为前提；这两点比宿主宽，但密钥不对就解不开。
- 密钥只在内存，不落盘、不进日志与诊断；取钥失败只记录不含敏感信息的原因分类。
- 宿主没有钥匙串模块时（3.17.x 及更早，凭据仍是 `enc:v1`）行为与此前一致。

## 状态所有者与接口

- `quota-client.cjs`（分片 `src/quota/00-constants-and-crypto.cjs`）拥有全部解密逻辑与模块级密钥缓存（按凭据文件路径分桶，模块热换即重置）。`decryptHostCredential(value, j)` 是唯一入口，`j` 提供 `env`、`credsPath`，可选 `now`、`log`，以及测试用的 `keyringEntry`（钥匙串条目句柄）与 `keyTimeoutMs`。`decryptValue(value, key)` 只解 `enc:v1`，对其它 `enc:*` 返回 null。
- 钥匙串读取是异步的：密钥未就绪时本次调用按解不开返回；到位后通知已注册的额度 client 重新评估凭据并立即查询（额度与重置卡都关闭时不通知）。
  - 在途读取单飞。超时是软超时：读取走线程池、挂住时释不掉，超时只留日志，真正落定前绝不叠加新读取，迟到结果照常采纳。
  - 读不到或与条目 keyId 不符时，重试窗口内不再读取；已缓存的密钥不因一次读取失败而作废，缓存命中也不受在途重取影响。
  - 只有取到与此前不同的密钥才通知 client；取回同一把钥不触发重新查询。
  - 用户手动刷新、凭据文件变更与「拉取模型」的套餐路径会跳过重试窗口（在途读取稍后失败时同样生效）；时钟回拨时从回拨后的时刻重新计窗。
  - 取钥失败经调用方注入的日志记录原因分类（不含密钥材料）；发起读取的调用方才有该日志。
- 凭据重评发生在每次载荷推送：除首次读取与重试外不得读钥匙串。`env` 来源是文件时每次重评都会读该文件（桌面常态是 `os` 来源）。
- 额度 client 创建时注册通知回调，`dispose()` 时注销；注销后到位的密钥不得再触发查询。密钥到位、首轮查询在途期间，数据源状态是待查询而不是未配置。
- `model-puller.cjs` 仍接收主桥注入的 `decryptValue`；套餐 token 解不开且条目为 `enc:v2` 时改经 `decryptHostCredential` 解密（调用时才取模块，热换后用的是新模块）。
  - 「列出供应商」是主桥同步取值的接口：钥匙串密钥尚未进缓存时，这次列表不含套餐源，但会触发读取。
  - 渲染端在用户选中的是套餐源而列表不含它时，稍等重问一次；仍没有则提示凭据暂不可用，不得改投其它供应商。

## 验收场景

1. `enc:v2:env` 与 `enc:v2:os` 条目在密钥可得时解出明文；额度、订阅、Start Plan、重置卡与套餐模型请求头均为明文 token。
2. 密钥不可得、keyId 不符、密文被篡改、iv 或 tag 长度不符、来源不是 `os`/`env`、未知代际：解不开，零请求。
3. 钥匙串密钥异步到位后，无需等待低频探测即恢复查询；到位前与读取失败期间零请求，且不反复读取；一次读取失败不影响已缓存的密钥。
4. `enc:v1` 与明文凭据的行为不变。
5. 主桥注入的 `decryptValue` 无论是只认 v1 的当前实现还是旧的透传实现，套餐模型拉取都不外发密文。
6. 选中套餐源而列表暂不含它时，不向任何其它供应商发起拉取。

## 未验证

- Windows 凭据管理器与 Linux secret-service 走同一条链，未实机验证。钥匙串条目按凭据文件绝对路径定位，Windows 上路径拼写（盘符大小写、8.3 短名、home 目录来源）是否与宿主逐字符一致未验证，不一致时表现为取不到密钥。
- `env` 来源只有夹具验证和对宿主实现的静态对照，没有真实的 managed secret 环境。
- 钥匙串被锁定或需要系统授权时的表现：只在一台 macOS 机器上观察到读取即时完成、未被阻塞。
