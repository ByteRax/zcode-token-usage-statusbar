# app.asar 手机补丁合并

## 目标与边界

独立安装 `install.py` 和插件 `/install-overlay` 共用 `patch_install.py`。宿主布局通过手机钩子校验时，loader 和手机钩子在同一次归档提交中写入。布局不支持时仍可安装 loader。SessionStart 在已有 loader 的归档中补装手机钩子，保留当前 loader 路径。统一归档 CLI 使用 `install`、`remove`、`check`，卸载仍走既有入口。

## 归档变换

- 修改对象是 `@zcode/desktop` ESM 主入口 `out/main/index.js`。loader 动态 import 尾缀与手机中段钩子从同一份源入口生成，作为同一项归档修改进入现有 stage、校验与提交流程；不得先后重打包或对同一归档执行第二次替换。
- 手机补丁沿用既有指纹表和表外严格结构推导：校验唯一 stash 锚点、原始 uplink 回调及其 `currentBridge` 路由；保留对已知 v1、旧 v2、marked v2 和可识别半注入的升级/移除能力。未知、重复或混代标记、锚点歧义、目标包不符或 source map 布局无法验证时，不改手机代码；普通 loader 安装仍按既有规则继续。完整安装与卸载在读完入口后会为变换手机补丁再读一次归档，这次读档遇到 I/O 错误（含 Windows 上杀毒软件或索引器的瞬时占用）时同样不改手机代码：安装按「布局无法验证」继续装 loader（之后的 SessionStart 补装再补），卸载则失败并保留原归档，两者都不报成锁获取失败。完整升级和队列语义见[手机中继规格](mobile-relay.md#上行队列与补丁代际)。
- 卸载在同一份当前归档上剥离 loader，并仅在手机标记可识别时还原 stash/uplink；不能安全还原已存在的手机标记时拒绝重写。不得用旧 asar 备份回滚宿主版本。卸载沿用既有待替换规则：目标锁内先取消遗留的安装待替换包再重打包；SessionStart 遇到 remove 待替换包时让位，不自动安装。
- `check` 为当前归档追加只读手机诊断，沿用归档检查的退出码语义。手机状态有四种输出：`已注入`（stash 与 marked v2 上行均齐全）、`可升级或补齐`（存在旧代或可识别的半注入）、`未注入，可补装`、`无法检查（原因）`（归档读不出、宿主包不符或布局无法验证）。
- 用户运行目录中的旧 `mobile_relay_patch.py` 副本不由此次变更主动删除。共享/Release/运行清单及插件包清单停止分发它；同步恢复只兼容已存在的旧 journal 记录，不再创建该文件的新副本。
- 已有当前运行目录的唯一 loader 时，SessionStart 只补装或升级手机钩子，不迁移 loader 路径。先做只读入口检查，手机钩子已齐全时直接返回，不取构建锁或共享目标锁；存在 TMP/sidecar 才短暂取得目标锁回收已确认过期的自有空 journal 并检查是否仍有待替换操作。发现有效、损坏、孤立或符号链接形态的待替换文件时让位，不改写现有文件。
- 手机补装在共享目标锁外读取、变换、重打包，并完整校验源 SHA、stage 的 SHA/结构/语法及最终入口。手机钩子已齐全的只读快路径只读取同一归档句柄中的入口与包身份、复查便宜身份戳，不取任何 advisory 锁或扫描整包 SHA；只有确认需要写入后才在同一文件句柄读取源入口并扫描整包 SHA，绑定变换输入与源包身份。stage 使用独立构建锁与不匹配旧版/普通清扫 glob 的独立文件名前缀；手机清扫器只在持构建锁时清理过期残留。短提交锁内复查待替换文件、核对源归档与 stage 身份，并在原子替换前再核对便宜身份戳；已完成的 SHA/结构/语法校验不在锁内重复。手机提交按目标锁→marker 锁顺序，marker 锁仅零等待取得。补装事务持有该锁完成意图写入、提交和失败恢复。发生异常时以实际目标归档及已发布的待替换包身份判断是否已提交。确认两处均未接收本次 stage，且当前 marker 仍为本次意图时，恢复原始内容或移除本次新建的标记。已交换归档但写入 `publishedAt` 失败时保留未确认意图。混用缺少手机事务能力的旧 `runtime_lock.py` 时跳过需写入的手机补装，普通安装和监控收尾仍用原接口。源归档变化时丢弃 stage，最多按新源重建一次；stage 身份异常失败清理、不作为源变化重建；待替换冲突不覆盖、不合并。实际替换被占用拒绝时，在同一目标锁和 marker 锁内将同一份已验证 stage 发布为合法待替换包，并抑制 `publishedAt`，出锁后拉监控；监控仍须完整验包，仅最终交换归档后确认发布。其它 I/O 替换故障不冒充待替换排定；发布失败按既有 journal 回滚规则处理。
- 完整安装只在需要新包时记录发布意图，且必须先于 `_prepare_tmp`；无变化或复用已验证的相同待替换包不新建意图。意图失败时，完整安装不得创建 stage，手机补装须清理私有 stage，两者都不发布 TMP/sidecar 或替换归档。意图中的 `installation.entryHash` 必须是最终入口字节（含手机变换与当前 loader 行）的 SHA256；`publishedAt` 仅在实际替换归档后写入。
- 手机 hook 写入不受 `mobile_relay.enabled` 门控；SessionStart 只在对象内 `enabled` 为显式布尔 `true` 时输出手机提示。hook 仅在目标锁、独立构建锁或 marker 锁的 advisory 获取明确超时竞争时，按既有预算（首轮耗时不足 15 秒才重试，间隔 1.5 秒；SessionStart 总预算 60 秒）退避重试一次；意图写入异常、归档 I/O 超时、stage 校验失败、已有待替换操作、未知布局或其它错误不套用锁退避。显式安装仅在归档已替换，或待替换包已通过完整校验、身份未变且入口含本次手机变换时报告对应状态。整包读取或校验失败时不报告手机补丁已排定。
- 独立安装与插件 CLI 的手机输出：`patched` 打印「已写入」确认（客户端运行中要求完全退出并重开后生效）；`pending` 打印已排定、完全退出后自动完成；独立安装在手机布局无法验证而状态条安装成功时，先说明「布局无法验证，保留原代码」再输出完成。`pending`、`deferred`、`skipped-error` 不得输出「全部完成」式承诺。
- 已登记手机目标必须在剥离本项目已知注入和 loader 尾缀后同时满足原始资产 SHA 与两个锚点；锚点仍唯一但其它字节漂移也拒绝写入。表外目标仍按原有唯一结构推导，不因版本未知而拒绝结构可验证的往返。

渲染桥并入同一笔归档提交、以及重打包期间的整包读写收敛，见[归档单事务规格](asar-single-transaction.md)。

## 验收

| 场景 | 可观察结果 |
|---|---|
| 独立首次安装、插件首次安装或已有 loader 的 SessionStart 补装 | 布局可验证时一次归档提交包含 loader 与手机钩子。SessionStart 补装保留当前 loader |
| 完整安装或手机补装意图写入失败 | 完整安装在 stage 创建前失败；手机补装清除私有 stage；两者都不发布 TMP/sidecar、不替换归档；无变化及复用相同有效 pending 时不新建意图 |
| 实际安装意图发布 | 使用最终入口 SHA；替换成功前无 `publishedAt` |
| 已有手机钩子 / 有效、损坏、孤立或符号链接 pending | 已有钩子只读返回且不取锁；任何现存 pending 形态均让位，不改写盘面 |
| 手机补装构建期间另一个调用提交了归档或创建 pending | 重包、SHA 与结构/语法检查均在目标锁外；短锁复查并识别源变化或 pending，丢弃本次 stage/有限重建或让位；不覆盖并发结果 |
| 手机补装的原子替换因 Windows 宿主占用被拒 | 在同一目标锁内保留并发布同一个经过校验的 stage；`publishedAt` 维持缺省，只有监控最终交换归档后确认 |
| marker 锁竞争 / intent 写入失败 | marker 锁零等待且不重入；hook 只对明确锁竞争按预算重试，intent 写入失败不替换或发布 pending |
| 已登记版本中非锚点字节漂移 / 表外版本结构可唯一推导 | 已登记目标按 SHA fail-closed；表外目标仍可安装、检查、卸载逐字节往返 |
| 已有旧代或半注入 | 在已验证结构上升级/补齐；重复安装幂等 |
| 未知布局或手机锚点不唯一 | 保留手机代码；不妨碍既有 loader 安装；诊断为不支持 |
| 完整安装或卸载的二次读档被拒（如 Windows 瞬时占用） | 安装不改手机代码、照常装 loader 且状态为布局无法验证；卸载失败并保留归档；都不打印锁获取失败 |
| 完整卸载 | 单次归档提交还原本项目 loader 与可识别手机注入，保留其它资产和尾缀 |
| 已注入标记无法安全识别 | 卸载失败并保留原归档 |
| `check` | 报告手机状态，归档、TMP、sidecar 与配置字节不变 |
| 手机提示开关关闭或无效 | 不发手机补丁会话提示；归档安装、让位及重启行为不变 |
| 两次只读快照之间归档被并发改写 | 丢弃按旧入口算出的补丁，按新源重建一次；并发落地的宿主更新不被覆盖 |
| 目标不可写且归档只含手机钩子、没有 loader 行 | 卸载不按「未注入」免 root 放行，提示提权，归档字节不变 |
| hook 退避预算 | 首轮耗时达到 15 秒的锁竞争不再重试；hook 进程的监控环境变量在调用后还原 |

自动化验收使用 `tests/test_mobile_relay_patch.py`、`tests/test_mobile_relay_install.py` 与分发清单检查；宿主加载和持久钩子生效仍需完全重启后的实机验收。
