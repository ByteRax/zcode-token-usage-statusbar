# 归档单事务：读盘收敛与渲染桥并入

## 目标与边界

`patch_install.py` 的完整安装与卸载对 `app.asar`（现为数百 MB）的整包读取与写入做收敛，并让插件链的首次归档提交同时带上渲染桥。状态所有者不变：loader、手机钩子与待替换/监控链仍归 `patch_install.py`，渲染桥的指纹表与改写规则仍归 `renderer_bridge.py`，两者的编排只在 `overlay_install.py`。

不在范围：手机补装链（`install(mobile_only=True)`）的校验序列、监控进程的验包、卸载时的桥剥离，以及根 `install.py` 独立链的编排（它不补桥）均保持原样。

## 读盘收敛

- 来源归档的整包指纹仍在读取入口与重打包之前取得（`source_fingerprint(ASAR)`），这条不变。
- `repack()` 改为逐文件边读边写，不再把整包数据拼在内存里；产物字节与此前实现逐字节相同（头、对齐、偏移与 integrity 一致）。
- 重打包写 stage 时同步计算整包 SHA256。只有喂入的字节数等于 stage 大小才采用这份摘要；`repack` 被替身替换或没写满时回退为整包回读。
- stage 的身份戳取在 `chown`/`chmod` 之后；此后身份戳对不上即按既有 `PendingTmpError` 语义失败，不替换归档。
- stage 经同目录 rename 成为待替换包后，身份戳（体积、mtime、dev、ino）不变时沿用摘要，只换戳；对不上则回退整包回读。外部构建的桥 stage 没有写入期摘要，照旧整包回读，行为不变。
- 完整安装与卸载在同一把目标锁内刚生成并完整校验过待替换包时，把 sidecar 登记进本进程的校验缓存；紧随其后的替换只核对身份戳与 sidecar，不再整包重读来源与待替换包。监控是另一个进程，照常完整验包。
- 复用磁盘上已有待替换包（`_reusable_pending_install`）或走「已安装」早退时不登记缓存：前者不是本进程生成的包，替换前照旧完整验包。

## 渲染桥并入

- `install()` 新增可选关键字参数 `extra_modify`：无参可调用对象，返回 `None` 或 `{"source": <计算改写时的归档指纹>, "modify": {<归档内路径>: <bytes>}}`。钩子自己取指纹（整包哈希），`patch_install` 不把来源指纹交给它，免得「回显即通过」。
- 只在本次确实要生成新包时调用（已安装早退与复用待替换包两条路径都不调用），返回的改写与入口改写并入同一次重打包、同一次待替换包、同一次替换。
- 不并入的情形一律静默退回原两段式（安装完成后再由 `ensure_renderer_bridge` 独立补桥）：未提供钩子；钩子抛异常；返回形态不符；`source` 与本次来源指纹不一致；改写路径不在归档内、是外置（unpacked）或链接项、内容为空；改写触碰主入口 `out/main/index.js`。桥是旁路增强，任何情形都不得让 loader 安装失败。
- 并入后重启标记沿用主安装的 `pending-install` 标记（`entryHash` 仍是最终入口的 SHA256），桥不再单独写标记。
- 替换完成后，`ensure_renderer_bridge` 的只读判定应得到 `present`；不并入时其行为与此前一致。
- `renderer_bridge.plan_deploy(asar_path)` 是并入钩子的数据来源：只读，复用 `_inspect_deploy` 的判定与改写；已带桥、布局无法验证或读档失败返回 `None`。
- `overlay_install._install_overlay` 只在已加载的 `patch_install` 模块声明了并入能力（模块常量 `EXTRA_MODIFY`）时才传钩子；旧运行目录模块或测试替身没有该常量时调用形状不变。
- 卸载不并入桥剥离；独立安装链不并入桥。

## 验收

| 场景 | 可观察结果 |
|---|---|
| `repack()` 改写任意条目 | 产物与旧实现逐字节相同 |
| 生成待替换包 | `source_fingerprint` 只对来源归档调用一次；sidecar 的 `tmp.sha256` 等于待替换包实际字节摘要 |
| `repack` 被不经过写入期摘要的替身顶替 | 回退整包回读，安装照常成功，摘要正确 |
| 重打包后 stage 被外部触碰 | 安装失败、不替换归档、不留 sidecar |
| 客户端未运行时完整安装（本进程替换） | 来源归档只整读两次（指纹一次、重打包一次），整写一次；归档含注入行 |
| 复用已有待替换包后替换 | 替换前仍完整验包 |
| 钩子给出与来源一致的桥改写 | 一次重打包后 `ensure_renderer_bridge` 判定 `present`；全程只有一次整写 |
| 钩子异常 / 形态不符 / 来源指纹不符 / 路径不在归档 / 触碰主入口 | 不并入，loader 照常安装，不抛出 |
| 已安装早退与复用待替换包 | 不调用钩子 |
| 待替换包含桥（客户端占用归档） | 重启标记与主安装同语义；监控收尾后桥判定 `present` |
| 已加载模块无并入能力 | `install()` 调用形状与此前一致 |
| 手机补装链、卸载桥剥离、监控验包 | 行为与此前一致 |

自动化验收使用 `tests/test_pending_asar.py`、`tests/test_renderer_bridge.py`、`tests/test_plugin_runtime.py`；Windows 上「首次安装由两次完全退出收敛为一次」需实机验收。
