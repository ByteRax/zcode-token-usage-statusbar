# WorkBuddy 安装登记结构预检

WorkBuddy 安装器在备份、复制或写入任何文件前，须验证已有登记的结构：`known_marketplaces.json`、`installed_plugins.json`、`settings.json` 已存在时必须是 JSON 对象；`installed_plugins.json` 的 `plugins` 和 `settings.json` 的 `enabledPlugins` 缺省时可创建，存在时必须是对象；当前插件的既有安装记录存在时必须是列表，非空列表的首项必须是对象。`installed_plugins.json` 必须已存在（未装过客户端时提示先启动一次而非创建登记），`settings.json` 与 `known_marketplaces.json` 同样必须已存在且为对象。结构不符时报告字段并返回失败，不修复、覆盖或删除用户数据，也不创建备份和插件目录。合法登记仍保留其它条目及已有安装时间；既有记录缺 `installedAt` 时以当前时间补写，不写入 null。

验收：隔离临时目录中分别覆盖空值、列表、字符串等异常结构（含文件顶层非对象形态），以及异常的当前插件记录；验证返回失败且目录内容逐字节不变。正常与缺省字段场景仍可安装，保留无关登记。

卸载同样在备份、删除登记或目录之前检查现有三个文件及其嵌套字段：缺失文件视为空登记，已存在但无法解析或结构不符时拒绝操作，避免只删除部分登记。

只读的 `--check` 遵循同一判据：三个文件已存在但无法解析，或文件及 `plugins`、`enabledPlugins` 嵌套字段结构不符时，报告原因并返回失败，不折叠为空登记、不抛异常、不写任何文件；当前插件的安装记录仅在其为非空列表且首项为对象时计入就绪，异常记录按未就绪处理而不是在检查中途崩溃；记录就绪但 `installPath` 缺失或非字符串时按未就绪处理，不进入路径探测。
