# 桌面浮层与展示口径规则

适用路径：`src/overlay/*.js`、`scripts/build_overlay.py`、`overlay.js`（及 `plugins/zcode-token-usage-statusbar/overlay.js` 副本）、`turn-stats.js`、`inject-main.cjs` 中与浮层交互的推送/热重载/Git 状态段、`tests/overlay-*.test.cjs`。

改动浮层、tooltip、⚙ 面板、原生按钮增强、统计行或任何用户可见数字/文案前先读本文件；全局约定见根 [AGENTS.md](../../AGENTS.md) §4、§5。

## 1. 文件与版本契约

- **多文件分片与拼接**：桌面 `overlay.js` 源码按职责拆分为 `src/overlay/00-boot-state-i18n.js` 至 `12-instance-mount-and-boot.js` 共 21 个模块（`04-` 前缀七文件：`04-rotator-builtin-packs.js` 内置词包纯数据、`04-speed-v3-{charts,core,heat,view,wire}.js` 速度 V3 五分片、`04-status-rotator-data.js` rotator 其余数据与鲸鱼解码；`11-model-peak-factor-badge.js` 模型选择器峰谷倍率徽标（specs/model-peak-factor-badge.md）；`05-project-open-folder.js` 宿主项目菜单「在 Finder 中打开」注入（specs/project-open-folder-menu.md）；分片按文件名字典序加载，速度 V3 规格见 specs/speed-tooltip-v3.md），由零依赖脚本 `scripts/build_overlay.py` 拼接生成根 `overlay.js`（`python3 sync_plugin.py` 会自动先拼接再同步插件副本；`--check` 与 `test_plugin_package.py` 守护拼接产物逐字节一致）。日常修改优先编辑 `src/overlay/` 下的对应分片，再执行 `python3 sync_plugin.py`。
- `overlay.js`（位于 `src/overlay/06-instance-dom-and-styles.js` 的 `spawnInstance` 首部）的 `VERSION` 随**提交**递增，未提交的中间迭代不涨号；在 `06-instance-dom-and-styles.js` 中以多行 `/* VERSION 台账 ... */` 注释块维护（每行一个 `→ vNN` 条目），`scripts/build_overlay.py` 构建时自动收敛为单行 `//v82 ...` 同行注释以兼容发版台账检查脚本。
- 顶层常量（如 `SRC_FIELD_LABELS`、进度阶段表、签名缓存）必须在 `buildPanel` 等消费函数定义**之前**赋值，`var` 提升不会提升初始值，曾因时序在面板打开时崩溃。
- 浮层是注入宿主渲染进程的脚本：保留代际守卫（`__zusageDispose` 移除旧条再重注入）、幂等内容更新、tooltip 解绑与扫描清理；`rAF` 自调度必须在异常后继续下一帧；诊断对象原地更新，不替换闭包共享引用。
- 热重载：主桥按周期 stat 运行目录 `overlay.js`/`turn-stats.js` mtime（`hot_reload` 显式 `true`=2s、缺省 5s、`false`=关），变化即 cleanup + 重注入，`turn-stats.js` 先于 `overlay.js`。主进程新增推送字段时渲染端必须判空不渲染或整块隐藏——热文件可能先于冷文件部署，字段缺失是常态不是错误。
- 新增定时器、DOM/IPC 监听器要有明确归属，并验证热更新、导航、窗口关闭后停用；不能声称已有完整全局 dispose。
- **热路径性能预算（卡顿治理，规格见 [specs/perf-lag-reduction.md](../../specs/perf-lag-reduction.md)）**：流式期间的热路径是宿主 store 通知链内同步执行的 `turn-stats.js ingest`、100ms 心跳 `updateLive`、每帧 `track`——禁止在其中做 O(会话文本量 / 历史轮数) 的重活（整串 `Array.from`、全量轮表解包、整张 tooltip 串构建、整条 `render`）。新增逻辑按「未悬停 / 数据未变就不做」设计，打开瞬间补建（`drawTip` → `liveTipRefresh`）；v90「render 有 lastHtml 幂等所以 10Hz 空转无性能顾虑」的前提不成立（幂等只省 DOM 写，不省 html() 的字符串构建与 enhance* 全文档查询）；因此非 live 会话数据帧未变时整条 render 降频（间隔与 heavy 同量级，常量见 08 分片 updateLive；ctx 环/额度 chip/git chip 的 reapply 对账因此变慢，仍由 render 与 heavy 两处承担，需实机留意原生外观被 React 重写后的恢复时延）。**度量先核对 `document.visibilityState`**：窗口被遮挡/隐藏时定时器降到 ≈1Hz、rAF 停发，度量会显著低估前台成本。配方：CDP `Profiler.start` 采样归因 + `Profiler.startPreciseCoverage({callCount:true})` 取函数级调用频率 + 页内直测 `ZUsageTurnStats.createTracker`；Python 侧用只读真库 + 隔离 HOME 起 `zusage.py serve` 按 1.5s 节奏计逐帧耗时（在仓库目录下跑 serve 会让价表同步线程写出 `pricing-cache.json`，测完必须清掉）。 **桥读取同属热路径（issue #309，规则 10–12）**：桥包装的 `getState()` 在 v2 桥下是 O(window) 的整窗深拷贝（窗口可达数千行，不是固定 60 行），100ms 心跳与每次通知处理里**禁止直接调它**——心跳读 handle 上的快照记录（`handleSnapshot`，≤2s 回源一次兼作探活）、通知回调用 `subscribeStore` 传入的 `changed(state)` 而不二读；通知处理另按实测成本自适应合并（≥8ms 才生效，廉价会话逐字不变）。新增任何读 `bridge.handle.store` 的逻辑一律走 `handleSnapshot`。**VM 夹具陷阱**：overlay 夹具的 `performance.now` 是不随真实耗时前进的假时钟，夹具内 `subscribeStore` 测得的处理耗时恒为 0，预算永不触发——验证预算要用 `turn-stats.test.cjs` 的注入时钟单测或真实时钟基准，别在夹具里数读取次数得结论。
- **卡片内嵌形态的 `track` 不逐帧读几何（v444，issue #452，规格规则 19）**：条内嵌在输入卡片里随卡片排版，`track` 在 `cardMode` 为真时每帧只保留「补挂对账」（`bar.parentElement !== (cardHost || cardCache)`）与门前的超限气泡同步（纯 DOM 引用读取；气泡显示时它逐帧读两个矩形，门控对它无收益），几何段按「有脏标、`cardMode` 翻转、视口变化、条面横向滚动立即执行；面板/子代理浮层/⋯ 菜单打开或视口保持期内逐帧；否则按 100ms 兜底」门控，时钟回拨视为到期并作废保持期截止时刻。宿主每帧改 DOM 时逐帧读几何，会把本帧的样式重算与布局强制进本回调。**新增逻辑的三条纪律**：①新增需要逐帧跟随的浮层时，必须把它登记为门控的不设门条件——脏标只换一次几何段，「打开期间置 `trackDirty`」达不到逐帧跟随；②新增「内容变化后需下一帧重判几何」的路径，在变更点置 `trackDirty = true`（先例：`render()` 重建条面、`dedupBars()` 解除抑制、条面 `scroll`）；③验证门控的用例必须先冻结夹具时钟再跑首帧，首帧之后才冻结会让「不足一个节奏」的边界随真实耗时偶发翻转；既有用例里断言「某帧之后几何结果变了」的地方，断言帧前要推进假时钟满一个节奏，否则帧被门控跳过、守卫改坏了也不红。药丸与 below-card 悬浮形态不设门，仍逐帧。实测数字只写在规格的证据段，不抄进本文件。
- 渲染测试 harness（如 `overlay-cost-tip.test.cjs`）按**源码整行字符串**打补丁取内部状态（例：`for (var i = 0; i < els.length; i++) els[i].__tip = h.tips[i] || null;`），改写这类行会让 `replace` 静默失配、一批用例同时变红且报错毫无指向——需要在附近加逻辑时另起独立语句，不改原行。
- 块注释内枚举选择器/通配项用顿号或破折号分隔（如 `.zu-src-field、.zu-mp-*、.zu-notes-*`），注释文字里不得出现 `*/` 序列——它会把块注释提前闭合，构建产物直接 SyntaxError，且 `node --check` 报错行常指向注释之后，难定位；写完含通配的注释立即对构建产物跑 `node --check`。

## 2. 挂载与几何

- 默认状态条优先挂输入卡片工具行之后，找不到工具行时，问询/权限确认面板卡（`data-elicitation-dialog-card`）改挂面板内容列末行（`data-elicitation-dialog-footer` 之后，无 footer 退化整卡末尾，v408），其余才回退到 body 级 `position: fixed`；样式挂条内 `<style>`。药丸样式固定在所属输入卡片下方、按内容定宽并居中。几何避开输入框中心点命中检测，避免自遮挡闪烁；面板和 tooltip 挂 body。**悬浮形态（药丸 + 兜底）必须裁剪滚动内容（v491，issue #517）**：ZCode 4.0 把 composer 以 sticky 悬浮在可滚动消息列表 `[data-testid="v4-timeline"]` 内部，列表内容延伸到视口底、会从悬浮条背后穿过（v143 让位机制只把输入卡顶上去、不裁内容）——track 悬浮定位拍按裁线 `min(条上缘, 输入卡下缘)` 给所属 pane 的 timeline 写 `clip-path: inset(0 0 Xpx 0)`（每帧幂等；document 级兜底必须 `tl.contains(composer)` 归属校验，防多 pane 误裁；pillUnsafe 条安全隐藏时不裁）；条隐藏（hideBar）与让位归还（releasePads，切档/换卡/销毁共用）同步清除。找不到 timeline（旧版宿主/异形布局）自然降级不裁；clip-path 只裁绘制、不改 fixed/absolute 后代定位基准。
- 默认样式卡内随卡片拉伸，悬浮回退锁定卡片实测宽。**超宽行为分四层降级（v352 定案，窄宽收缩与优先级折叠串联）**：①完整条面 → ②`zu-tight` 缩字号收间距（窄宽状态机，脱离布局探针量自然宽，250ms 节流+双向 +24px 迟滞）→ ③`zu-narrow` 藏本轮/会话/今日/项目的次要计数（tooltip 保留）→ ④**优先级折叠接管**（仅 shrink===2 仍溢出时；`zusage3.barOrder` 定显示序、`zusage3.barPriority` 定折叠序，低先折、同级右先折，system 徽标与 speed 格 rank=-1 排最后候选（普通候选收尽仍溢出时照折，并非豁免）——speed 是「固定（始终显示）」语义，无有效数据仍不渲染不伪造 0；整格折进「···」菜单，body 级实例闭包，格名走 00 分片 `ZU_BAR_TITLES`，实时值原地同步）；全折仍装不下回横滚 + `zu-clip`/`zu-clip-left` 双向渐隐兜底。折叠迟滞带 FOLD_HYS=24px 防阈值震荡，**折叠触发器必须双向**（单向溢出探针在「已折叠且刚好装下」直接变宽时冻结折叠集，pill 夹具实证）；居右对齐首格被折叠由 `data-zu-endlead` 挪到首个可见格接管。排序/优先级定向写（persistBarOrder/persistBarPriority）+ storage 回读同步，syncPanel 双回填。窄宽收缩契约见 [specs/statusbar-narrow-layout.md](../../specs/statusbar-narrow-layout.md)、折叠契约见 [specs/statusbar-layout.md](../../specs/statusbar-layout.md)。药丸样式以输入卡及视口宽度约束，窄时条面横向滚动，聚焦条目应滚入可视区域；条面不换行。
- **宿主标题栏拖拽区穿透（v254）**：Electron 桌面宿主多视图顶部有 48px `[app-region:drag]` 标题栏拖拽条，拖拽区按几何命中、穿透上层未显式标注 `no-drag` 的覆盖层（宿主自家每个浮层都标 no-drag、并用全屏 `no-drag` 屏障）——挂 body 的浮层根（`.zusage-panel`/`.tip`/`.zu-mp-ov`/`.zu-compact-dlg`/`.zusage-exc`）必须显式 `-webkit-app-region:no-drag` 把自身矩形从拖拽区减掉，否则与条带重叠的头部（如设置面板 top:8px 的 ✕、极矮视口下 top clamp 8px 的超限气泡）真实点击被窗口拖拽吞掉。**新增 body 级浮层根必须挂进该规则**（`tests/overlay-settings.test.cjs` 有规则串与类名挂载点双断言）。「✕ 点不动」另一已定案根因是命中区过小：`.zu-settings-close` 以 `::after inset:-6px` 外扩命中与 hover 反馈（事件链无缺陷，原始 20×24 矩形点不出 head 空白），重排 head 勿裁掉；定责先用 CDP 真实鼠标 + `elementFromPoint` 命中网格采样排除事件链问题。
- ⚙ 通用的「状态条样式」持久化为 `zusage3.theme`（`default` / `pill` / `compact`，缺省与非法值回退 `default`），主题切换只写该键，同窗实例同步。**v226 自动精简例外**：六个格开关（turn/win/proj/tools/today/sub，`SHOW_CELLS` 在 setBarTheme 旁）全部关闭的**边缘触发**自动切 compact（default 与 pill 来源都触发；git/subRate 不在条面不参与），`zusage3.autoCompact` 记录来源主题，重开任一格恢复并清标记；面板手动改档即清标记解除自动（无标记不写，边缘触发保证手动改回默认不立即翻回；残留标记在重开格子时防御清理）。手动选精简不带标记，不自动切回。药丸表面跟随所属输入卡的圆角、边框、背景以及 Highspeed/焦点状态；不改变数字单位、额度口径或工具栏 chip。
- **底栏「重启 ZCode」按钮（v379）**：⚙ 面板底栏 `.zu-settings-foot` 滚动提示左侧常驻一枚「重启 ZCode」按钮（`L("重启 ZCode","Restart ZCode")`），与「插件更新」分区内的同名按钮**共用** `data-update=relaunch` 点击委托与同一状态机（`relaunchSiblings`/`eachRelaunch`，09 分片）：二次确认、正在重启禁用态、4s 无回执/失败/90s 仍存活三路还原全部同步到两枚；`syncUpdate` 用 `querySelectorAll('[data-update=relaunch]')` 把 armed/sent/禁用/待重启高亮广播到两枚（任一枚 `sent=1` 即两枚禁用），`querySelectorAll` 缺席的 VM 切片回退 `querySelector` 单按钮保持旧契约。两枚按钮均受 v180 `relaunchSupported` 能力门控（缺标记隐藏+手动指引）与 v244 定时器随实例 dispose 清理约束；新增第三枚同 action 按钮自动纳入同步。因 `eachRelaunch` 按拍重新 `querySelectorAll` 取当前 DOM，面板在重启等待期被 `buildPanel` 重建后闭包捕获的 `button` 已脱离 DOM：故 ok 回执守卫改读当前 DOM 的 `sent`（`eachRelaunchSends`，不可读闭包旧节点），且 4s 回执/ok/90s 三路回调以实例级 `relaunchSeq` 代际号校验（过期回执丢弃），防「4s 超时已还原→迟到 ok 重挂 90s alive→误清新一轮重启」；5s 确认定时器存 `relaunchConfirmTimer`，发送与 dispose 两路清理。底栏按钮样式复用 `.zu-settings-feedback/.zu-settings-contact` 同款外观（`.zu-settings-relaunch`），待重启红边沿用 `.zu-rr-armed`。

## 3. React 对抗与宿主 DOM 挂靠

- 三板斧：① 宿主元素上用 `data-zusage-*` 属性驱动 CSS（React 不清理非 props 属性；改 class 会被 className 整串重写抹掉）；② 静态几何用 CSS 覆盖 SVG presentation attribute；③ 动态 dasharray/pathLength 由 JS 写入并在 render 与 heavy（600ms）两处 reapply 兜住 React 重写。
- 要继承宿主 hover-card/原生交互的手动节点必须挂进 React trigger 元素**内部**末尾（宿主 children 为单元素时末尾手动节点不进 diff）；挂 wrapper 兄弟节点不触发 hover-card。React 提交可能挤位，每次对账 `if (el !== parent.lastChild) parent.appendChild(el)` 挪回。

## 4. tooltip 与监听预算

- Chrome 在悬停链重算时会向 `documentElement` 补发**伪 mouseleave**（格内 flex 空隙、tooltip 子元素间必发）。边界判定用 `document.querySelectorAll(":hover")` 的最深元素甄别：最深为 null/body/documentElement/IFRAME/WEBVIEW 才真离开，否则忽略交回 mousemove 流。`relatedTarget` 与坐标 `elementFromPoint` 方案已实测否决。伪事件只在真浏览器出现，VM/stub 测不出，改悬停边界必须 Playwright 实测（见 [tests.md](tests.md)）。
- 滚动收起分层：`hideTipsOnScroll` 只收消息流内随滚动移位的 rateTip；quotaTip/gitTip 挂在固定的 composer 工具行，滚动豁免；chip 随宿主 React 重建而 detach（无 mouseleave）时由扫描 tick 的 `isConnected` 健康检查兜底收起。
- 监听预算：浮层 tooltip 共用**单个** scroll 监听，新增浮层不得再加 scroll/resize 监听；每个 tooltip 有解绑路径。
- 凡「周期对账 + innerHTML 重写」的浮层（gitTip/quotaTip/chip）必须走内容签名幂等（`__zuTipSig`/`__zuSig`，签名不变跳过重建），否则滚动拖拽被打断；数据真变时保留 scrollTop 后一次性重建。
- 自绘 tooltip 走 rateTip 同款独立浮层模式；标题与 ⚙ 面板开关标签是两套措辞，文档按两套区分。
- **激活方式（v249 点击开关 + v440 悬停门槛，issue #445）**：`zusage3.tipClick` 缺省关=悬停显示，仅显式 `"1"` 开=点击激活：mousemove 在保活/收起分支之后单行早退（点开的 tooltip 仍靠上方分支保持/收起），打开一律走 `bar.click` 的 `.it` 分支（再点同格 `re-click` 收起、`focusTipAt` 记录 focusin 时刻防「focusin 先打开、click 紧接着按再点关闭」的首击抵消；.zu-sub 的 click→pinned 打开是 v246 既有契约不受开关影响），子代理 hover preview 在点击模式下关闭。⚙ 通用分区「点击激活悬浮窗口」，两处回填（buildPanel 尾部 + syncPanel）必须齐。键盘 focusin 两模式都即时打开。fxTip、速度柱状图信息卡、6 个工具栏 chip 与宿主原生 hover-card 不在此链内，别误接。**悬停门槛（v440，issue #445）**：条面悬停明细与子代理 preview 不再划过即显——`zusage3.tipHoverMs`（默认 500，⚙ 通用「悬停显示延迟」下拉 100/500/1000/1500/2000ms；下拉无「立即」档，0=恢复 v246 划过即显仅可手改 LS，其余手改允许 0–10000 整数）内 mousemove 命中换格走 `tipHoverSchedule` 排程（08 分片，同格续期不重置等待），到点 `tipHoverFire` 按 `lastPt` 坐标 `elementFromPoint` 重命中复核（150ms 节流间隙指针可能已离开/换格——复核不过不弹 fail-closed，漂移改靶重排：指针停在任意格最迟停下后约一个门槛时长内弹出）；取消路径：panel-hover/left-bar、真边界跃迁（tipLeaveAt 伪边界过滤后撤销、tipBoundaryHide blur/edge——撤在守卫之前，dwell 非按压交互）、focusin（键盘优先）、改档（含 chip 单槽）、dispose。chip 家族扩展：git/速率（精简 .zu-tsb）/重置卡/套餐额度/增强记录/系统状态六枚工具行 chip 与流内子代理速率·工作流卡·状态面板行 chip（`subTipDocOver` 委托）同走该门槛——01 分片模块级单槽 `zuChipHoverArm/zuChipHoverDisarm`（key=chip 元素本体；chip 有精确 enter/leave 对，无需到点复核；同 chip mouseover 重入不重置等待、换 chip 自动作废、fire 时 isConnected 守卫+槽身份自校验防过期回调），六处 mouseenter 包门、mouseleave 补 disarm，focus/blur 键盘路径保持即时，`disposeOverlay` 统一撤排程；fxTip/档位说明（tooltip 内 ？ 小目标）与齿轮更新日志卡（红点门控）有意不进门；回答末尾确定性统计行无悬停浮层，无需门控。**测试夹具契约**：VM 切片/全源夹具的 state 无 `tipHoverMs` 时门槛按 0 直通，既有 chip 测试零感知——全源 harness（git-chip/git-multi/git-responsive/ctxbtn/prompt-enhance/quota-chip-harness/tps-chip/quota-opencode-model）已显式种子 `tipHoverMs=0`（注释「本文件测开门后行为；门槛链由 overlay-tip-activation 锁」），新全源 harness 若悬停受门面须同款处理。与 v247 已移除的 1000ms 停留链无代码关联，符号名不同（`tipHover*`/`zuChipHover*` 非 `hover*`，`overlay-tip-activation.test.cjs` 的 v247 符号反锁仍生效）；点击激活模式下条面链不排程；真机验收注意 Chromium 隐藏窗口对 setTimeout 密集节流会把门槛定时器拖到分钟级——harness 须加 `--disable-background-timer-throttling --disable-renderer-backgrounding --disable-backgrounding-occluded-windows`，前台窗口无此问题。
- **确认类交互统一自绘弹框（v350，用户拍板 2026-11-15）**：overlay 内一切「破坏性/不可逆操作确认」（删除、清空、移除凭据、丢弃修改等）一律走 `zuConfirm(title, desc, okText, onOk)`（01 分片），**禁止新增 `window.confirm`**——原生框样式不可控（英文 Cancel/OK、系统灰壳）与宿主视觉割裂，且 Electron 下模态劫持窗口。`zuConfirm` 复用压缩确认弹框 `.zu-compact-dlg/.zu-compact-card` 全套类（遮罩/卡片/取消描边+主操作实底按钮/缩放动画/prefers-reduced-motion），零新样式；交互协议同压缩弹框：Esc（capture+stopPropagation）/遮罩 mousedown 关闭、Enter 触发主按钮（焦点逸出弹框则不劫持宿主 Enter）、打开即 `ok.focus()`。既有类名受热更清理选择器（00 分片 `.zu-compact-dlg`）与 `-webkit-app-region:no-drag`、`modalOpen`/面板外点白名单豁免清单覆盖，新确认弹框必须继续挂这两个既有类名而不是另立外壳；document 级 keydown 带热更 `stale()` 自卫。测试侧用 ctx 桩替身 `zuConfirm`（注意 VM 切片内 `function zuConfirm` 声明提升会覆盖运行前赋的桩，必须在 `runInNewContext` **之后**覆写）。

## 6. Git 状态 chip

- 数据链：渲染端 `publishGitPaths()` → 主进程 `gitTick`（fs watch 驱动，各窗路径并集）+ `git-refresh`（路径集变化立即首查、点击回退立即执行）→ `gitState` 推回。**刷新时机对齐宿主原生 Git 胶囊（v420，规格 [specs/git-chip-host-sync.md](../../specs/git-chip-host-sync.md)）**：主进程对路径并集建 fs.watch（工作区非 Linux 递归 + `rev-parse --absolute-git-dir/--git-common-dir` 解析的 .git 元数据目录恒递归），任一事件重置 60s 尾随防抖（宿主 `GIT_AUTO_REFRESH_DEBOUNCE_MS` 同值同型），静默满 60s 跑一轮全路径查询；watcher 随路径并集增删，创建失败仅记日志**不回退轮询**（宿主同策略）；渲染端不做快照驱动的节流重查（v420 移除）。持续写文件期间防抖顺延（活动停止后最多 60s 才更新）是宿主同款节奏，勿当 bug「修回」轮询。命令 `git -C <p> status --porcelain --branch -z` + `diff HEAD --numstat -z`（v433 起 -z 对齐：非 -z 的 porcelain 引号路径与 numstat rename 箭头串会让含空格/箭头文件名丢每文件 ±N；-z 的 porcelain rename=新名段+旧名段，numstat rename=ins\tdel\t\0旧名\0新名\0），env `GIT_OPTIONAL_LOCKS=0`、`LC_ALL=C`、`GIT_TERMINAL_PROMPT=0`；无提交仓库 `diff HEAD` 退 128 属预期。
- **点击唤起原生胶囊弹层（v420）**：chip 点击（含 Enter/Space）优先在 pane 节点（`wantedEl` 上溯 `data-session-id` 根并校验 sid）内查可见的 `[data-status-capsule="git"]`（`getClientRects` 非空），命中即派发 pointerdown/mousedown/pointerup/mouseup/click 合成序列（坐标=胶囊中心）由宿主 Radix 打开原生弹层，不发起 `git-refresh`、不进 busy；未命中（干净仓库宿主不渲染胶囊、旧宿主无该结构、胶囊隐藏）回退原有立即刷新链（busy/requestId 回执/scope 迁移保护全保留）。多仓父目录宿主无胶囊，恒走刷新回退。**弹层定位迁移（v422，规格 [specs/git-chip-host-sync.md](../../specs/git-chip-host-sync.md)）**：开层后对 popper wrapper 设独立 `translate` 属性把弹层迁到 chip 正上方——该属性与 Radix 写的内联 `transform` 叠乘且 Radix 不写它，禁用强改 `transform` 的方案（会被其定位引擎反复覆盖）；胶囊自身点击不迁移。
- **受管 worktree 路径覆写（v407，规格 [specs/worktree-branch.md](../../specs/worktree-branch.md)）**：宿主分栏 `workspacePath` 对 worktree 会话是项目主目录（宿主 §2.1「带 workspace 的字段只表示归属」，ZCode 自家 Git 面板用 `gitCwd = task.cwd`），直接查 git 读的是主 checkout——快照顶层 `worktrees`（`zusage.py` `include_worktree` 桌面链门控，sid→`{cwd, root, bucket, name, ref, sha, created, sourceRoot}`（v409 扩），事实不可变走 `_WT_FACT_CACHE`：只有 session 行存在且 directory 非空才写缓存，未落库不写负缓存，起点未决（ref/sha/created 同 None）命中也重查）按 sid 给出真实 cwd，`worktreeFor` 命中即覆写发布、显示与点击刷新路径；tooltip 单仓路径加「受管 Worktree」（bucket·名称）、「Worktree 根目录」（仅 cwd≠root）、「主仓库」（sourceRoot）、「起点」、「创建于」数行（v409 重组）。游离检出令牌：chip L0/L2 摘要与 aria 三处显 `worktree`（v409 引入 v410 改小写，`gitBranchToken` 单源，aria 为 `worktree（游离检出）`），有分支照常显示分支名。worktree 目录被删（冷=从未查过、热=查询后删除被 `gitPathOk` 滤除）时主进程对消失路径**补推一次 notrepo**（gitTick 内 `gitMissingNotified` 按「窗口×路径」去重，恢复即解除、再消失重新通知）→ chip 摘除，**绝不回退主 checkout 显示**；该补推在 `inject-main.cjs`（冷文件，改它必须完全重启）。非受管/缺帧/远端行为不变。
