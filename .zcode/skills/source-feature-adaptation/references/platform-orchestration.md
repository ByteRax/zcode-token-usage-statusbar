# 在不同编程 Agent 中使用并行编排

本 Skill 描述工作流，不会自行开启当前宿主不存在的 Subagent 能力。运行前检查当前会话暴露的真实委派接口和权限；不可只凭本文假设已拥有对应功能。

## Claude Code

- 官方子代理机制可使用内置 Agent 委派，或按实际版本在 `.claude/agents/` 配置自定义代理；查看 https://code.claude.com/docs/en/sub-agents 。将研究/审查工作交给只读子代理；写入任务优先使用隔离工作树（支持时采用 `isolation: worktree`），并始终由主代理统一整合。
- Agent Teams 适合有大量独立工作单元和跨会话协作的任务，但属于**实验性**能力，具体启用与限制取决于宿主配置；查看 https://code.claude.com/docs/en/agent-teams 。不要私自修改用户全局配置以强行开启。
- 不为每项小任务都创建持久自定义 Agent；优先用动态任务信封。需要重复使用的角色再按宿主支持方式安装。

## Codex 及其他支持 Subagent 的运行环境

- 使用环境真正提供的委派/并行工具，并尊重其限制；不要把某个版本、某个 API 的具体工具名当作所有 Codex 宿主都具备的接口。
- 参考 OpenAI 多代理指南： https://developers.openai.com/api/docs/guides/agents-api/multi-agent 。并行研究和互不重叠的代码变更适合委派，串行依赖链和共享文件写入应由主代理协调。
- 允许以独立工作树、隔离分支或补丁结果交付代码时，必须检查工作区未提交修改并核验集成产物，不以子代理返回内容等同合并成功。

## 环境退化

1. 能并行调度但不能隔离文件：分析/审查并行；编码仅对非重叠文件并行，否则串行。
2. 只能派只读代理：只并行分析，主代理负责修改与测试。
3. 不能派任何代理：保留完整的取证 → 适配 → 直接实施 → 验证流程，不模拟“已创建 6 个子代理”。

在最终报告中只陈述**真实使用的**子代理角色和成果；如果降级，说明原因即可。
